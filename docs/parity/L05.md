# L05 — SQLite semantic store and atomic publication

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(intelligence): persist and publish native SQLite snapshots`.

`kode-intelligence/src/store/` replaces the internal H2 cache with pinned rusqlite
0.40.2 and bundled native SQLite. The connection opens and remains exclusively on
the dedicated `KodeSQLite` thread. A bounded 16-request queue returns typed tagged
tickets; readers clone immutable published snapshots without database I/O. Orderly
shutdown closes submissions, drains accepted jobs and joins off the application
thread. Startup/drop guards prevent detached writers, including abandoned startup.
Fallback Drop joins synchronously; application owners should await shutdown.

[Schema v1](../../crates/kode-intelligence/src/store/schema-v1.sql) stores raw file
deltas separately from normalized resolved scopes/symbols/occurrences/relations,
full recursive type shapes, expressions, lexical spans, unresolved types, imports,
hints, dependencies and generations. Indexed compatibility definitions/usages
retain every source metadata distinction, with explicit byte ranges and UTF-16
columns. Signed semantic IDs and unsigned 64-bit revisions/generations round-trip
without SQLite integer truncation. Complex type JSON retains generic, nullable,
function, union, primitive, named and unknown shapes.

Each commit validates/canonicalizes facts and replaces only files whose complete
raw/resolved/compatibility bundle changed. Unchanged dependent relations and
generations remain intact. Identical expression ranges keep the strongest fact;
empty expressions and identical stable records collapse consistently. Explicit
compatibility replacements are atomic with semantic facts. Omitted compatibility
data is retained only for unchanged source content, avoiding stale token ranges.
The transaction also updates types and the global semantic revision. Publication
occurs after COMMIT, preserving previous Arc snapshots during preparation/writes.

An immediate transaction checks the prepared base revision before replacement.
Another cooperating writer requires reload rather than silently overwriting newer
facts. Reusing an unchanged revision retains snapshot identity; changed facts
require advancement. Cancellation checks and SQLite VM progress interruption
preserve the prior transaction/publication. A successful commit still publishes
if cancellation arrives after the durable write.

Disk mode owns only `.kode-rs/index.sqlite`; memory mode needs no project or Java.
Application/schema markers and a byte-model/grammar-manifest signature identify
rebuildable caches. Incompatible owned schemas/signatures rebuild; explicit rebuild
and transactional clear APIs are available. Foreign/corrupt unidentified files,
nonregular paths and cache-directory/file/sidecar symlinks are refused. The legacy
`.kode/db` is untouched. No listener, H2 process or JDBC bridge is involved.

Ten storage tests comprise seven integration tests in `tests/sqlite_store.rs` and
three worker tests. They exercise restart with all type shapes and compatibility
metadata; maximum unsigned counters; duplicate symbols/expressions; unchanged
dependent facts; snapshot reuse; stale/cancelled/cleared revisions; dropped-reply
critical writes; incompatible/explicit rebuild; foreign/corrupt/symlink refusal;
two writers; bounded queue saturation; old readers during pending publication;
SQLite failure after deleting old rows with full rollback; and real VM progress
cancellation followed by successful recovery. L01 validation also rejects missing
type/owner/scope references and excessive type shapes before persistence.

Limits are 64 MiB per JSON row, 512 MiB prepared file bundles, one GiB disk-file
inspection, bounded record counts, a one-second busy timeout and a ten-second
SQLite VM budget. These are service bounds, not a claimed process RSS limit.
No terminal check applies to this worker API. Resolver-produced Kotlin/C restart
scenarios close in L06–L08/L12; storage tests supply explicit resolved facts without
pretending the resolver already exists. L09 owns workspace/document result gating
and connecting source indexing to this store. Next ready task: L06.
