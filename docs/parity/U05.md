# U05 — Hex layouts and text or binary find

Status: done

M004 is implemented in the shared hex viewer. Header buttons select 8, 16 or 32
bytes per row, and F8 cycles them; the default remains 16. Changing widths keeps
the original top-byte anchor across row-alignment changes, cursor, selection and
temporary edits. Narrow panes retain the gutter and scroll horizontally to reveal
the active byte. Both hex and ASCII hit testing use the displayed byte identity.

Ctrl+F opens an independently focused find field. Tab toggles literal UTF-8 text
and binary hex pairs, either packed or separated by ASCII whitespace. Empty,
non-hex, odd-length and oversized patterns have explicit errors; the pattern
limit is 4096 bytes. Enter / Shift+Enter and F3 / Shift+F3 find next / previous
overlapping matches, wrap at the ends and select the exact bytes. Errors and no
match preserve the previous selection. Find never changes the buffer or file.

Linear KMP search runs on the existing bounded worker scheduler using a cheap
immutable byte snapshot. Both view and scheduler cancellation are checked during
scanning. Request, snapshot, query/mode and caret/selection proofs reject stale
results without consuming newer requests. Query/navigation/byte changes, Stop,
Escape, detach, disposal and shutdown invalidate work. Completion does not steal
focus. Stop leaves the field available; Escape also closes it, including when
F3 opened find from the byte body without moving focus.

The find field uses the existing native text clipboard worker and validates its
own paste request, focus, field visibility, mode, value and caret before applying
data. Closing and reopening cannot accept an old paste. Alt+C/X/V continues to
use the raw byte clipboard. Binary edits remain temporary, as documented by V02.

Validation on Linux x86_64 with stable Rust: **38 tests pass** across core bytes
(3), hex_viewer (4), hex_search (10) and app_runtime (21). The independent exhaustive
search oracle covers every binary input up to eight bytes, patterns up to four
bytes, every starting offset and both directions. Other cases exercise UTF-8,
NUL, row crossings, EOF, overlap/wrap, cancellation during repetitive scans,
layout round trips, edited buffers, narrow hit testing, tiny surfaces, stale
completion/paste, real worker publication, focus, cached views and workspace
disposal. Affected all-target Clippy with warnings denied, CLI build and format
checks pass.

[Four actual CLI terminal cases](U05-pty.json) pass: all three layouts and both
find modes at 200×30, 100×24 and 60×18, plus a 64 MiB repetitive search at 100×30.
They check exact row strides, mouse/key controls, Unicode across rows, EOF,
next/previous/wrap, malformed patterns, no match, F3 from the body and Escape.
The large case observes active searches before Escape, mouse Stop and file
switching, then edits and saves a different text file. Original binary bytes,
clean exits and terminal modes are verified. Observed Stop response was 11.17 ms
and file-switch response 22.75 ms in this local debug-build fixture, including
frame/poll cadence; these are observations rather than release-wide latency
guarantees. The distribution workflow runs the same fixture against its release
binary and uploads the resulting evidence. That remote run is not claimed here.

Reproduce with the stable toolchain, `cargo test -p kode-core --test bytes`,
`cargo test -p kode-tui --test hex_viewer --test hex_search --test app_runtime`,
and `python3 scripts/test-hex-search-terminal.py --binary <built-kode>`.
