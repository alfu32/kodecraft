# U03 — Optional downloadable Java runtime artifact

Status: done

The optional runtime builder, verified installer, managed-Java fallback and
production download UI are implemented. Qualification targets **Linux x86_64
GNU**, Rust **1.99.0 stable**, Temurin **21.0.9**, actual shaded helper and H2
**2.2.224**. Other platform artifacts are unqualified and unavailable.

F5/Get Java appears in the database panel and connection form after a typed
missing/unusable-Java error. Opening or declining the offer performs no download.
Acceptance rechecks Java first; a newly usable local JVM avoids metadata fetching.
Download runs off the UI thread with phase/byte progress, Cancel, Retry, Hide and
F4 wrapped/copyable details. Hide/Esc returns to editing; F5 reopens progress. Draft
fields/focus survive. Installation success requests an explicit Test/Connect retry
and never replays SQL or a database mutation.

The standalone jlink artifact uses the user's JDBC/auth/TLS module baseline plus
common driver modules. It contains standard JDK legal files, file hashes/sizes/
modes and a SHA-256 sidecar. It does not copy application/helper/driver bundles.
User-owned jlink files and flexible driver management remain untouched. The CI
workflow has immutable action pins and separate build/publication jobs. **Remote
CI and release upload have not run or been claimed**; Z03 retains complete release
orchestration/publication qualification. The public latest-release URL returned
HTTP 404 during inspection, with readable recovery in the production UI.

The installer resolves one metadata capture per attempt, selects exact platform
ZIP/checksum assets, bounds transport/extraction, validates archive and file hashes,
rejects unsafe/link/undeclared paths, probes Java 21+ and atomically publishes a
managed generation. Failure/cancel preserves any previous runtime and cleans owned
staging/locks; probe cancellation reaps its child. Construction and ordinary editor
startup perform no Java/runtime network work. Configured/local Java is preferred;
managed pointer discovery occurs only after a typed local-Java failure.

Acceptance evidence:

- Two actual jlink builds with the same JDK/epoch produced identical archives:
  **28,718,822 compressed bytes**, **48,986,496 runtime bytes**, **102 files**.
  SHA-256: `cc3fa68d913e91107ff72a69cbc5dee41822eb484de71b840cd17cb29901d386`.
- All **seven installer tests**, including explicit execution of the normally
  ignored actual-artifact case, pass. The downloaded image launches the real
  helper and executes `select 73 as RUNTIME_PROOF`. Local Java wins even when the
  managed pointer is corrupt. Synthetic cases cover metadata selection, corrupt
  archives/checksums/file hashes, traversal/symlinks/undeclared files, no probe
  before validation, missing/offline/malformed replies, sanitized errors,
  contention, cancellation/retry and owned probe-child reaping.
- [Twelve actual CLI PTYs](U03-pty.json), at 100/60 columns, cover no-local-Java
  download -> explicit connect -> actual H2 SQL, decline/core editing, corruption
  with retry, missing platform assets, HTTP failure with F4 details, cancellation
  with retry, quitting during active download, background download while editing,
  working local Java, Java becoming available before acceptance, and preserved
  connection-form drafts with explicit successful Test. Requests prove one metadata
  capture per attempt and zero fetches for decline or usable local Java. Files,
  credentials, staging/locks, helper reaping and terminal mode restoration are
  checked. The endpoint is a local synthetic release service serving the actual
  generated ZIP; no developer or production credentials are used.
- [Two package PTYs and manifest inspection](U03-package.json) qualify the actual
  release archive from a directory with spaces and an unrelated cwd: core/offer
  without Java and real adjacent-helper H2 SQL with local Java. No developer helper
  or Maven/JAR override supplies the packaged helper. The main archive has **no
  JVM**, 17 files and an exact payload/dependency manifest. Two assemblies from the
  same inputs match; this is assembly reproducibility, not independent Rust build
  reproducibility. Full installers, native library distribution, ttyd integration
  and notices remain Z03 work.
- Existing native bridge/driver/connection/execution/metadata regressions and
  application/service/JDBC qualification pass with explicit real-Java fixtures.
  The full TUI library/integration suite passes, along with affected all-target
  checks, workspace clippy `-D warnings`, format, credits and ledger checks.
  Local workflow YAML parsing passes; it is not remote CI evidence.

Reproduction uses `scripts/build-java-runtime.py`,
`cargo test -p kode-database --test java_runtime -- --include-ignored`,
`scripts/test-java-runtime-terminal.py --binary target/release/kode`,
`scripts/package-linux.py` (repeat with `--output target/distribution-repro`) and
`scripts/test-package-java-separation.py`. Build the native executable and JDBC
helper first. Detailed ownership and distribution handoff:
[integration contract](../migration/U03-INTEGRATION.md),
[Z03 continuation](../migration/Z03-INTEGRATION.md).
