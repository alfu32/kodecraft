# P01 — Server catalog, discovery and installation

Task: P01. Status: done.
Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`; reference tree clean.

Implemented `kode-lsp/src/{catalog,discovery,install}.rs`, bounded archive extraction
in `install/archive.rs`, settings reducer/rendering in `kode-tui/src/panels/settings/`,
worker/runtime/CLI composition, fixtures, reports and ledger. The frozen 10-server
catalog remains intact. Public contracts and limits are recorded in CONTRACTS.md.
Read LspCatalog.kt, LspService.kt's command resolution and SettingsView.kt. The
source manager's optimistic start flag is replaced by an acknowledged callback API;
actual LSP child transport is P02's responsibility.

Catalogs retain unknown fields, including manual package-manager instructions.
First compatible catalog version/download wins; arbitrary version strings are not
sorted. OS/architecture aliases cover Linux/macOS/Windows, amd64/x64/x86_64,
aarch64/arm64 and x86 variants. Resource/config paths, preferred commands, legacy
installed.json manifests and configured overrides work without downloading.
Commands remain argument arrays; symlink invocation names remain intact for rustup
and other multiplexers. Discovery does not create roots, alter executable bits or
run the discovered server. Corrupt manifests and missing commands are visible errors.

Reqwest 0.13.5, zip 9.0.1, tar 0.4.46 and flate2 1.1.10 APIs were inspected in their
selected local crate sources and exercised by the tests. TLS uses Reqwest's Rustls
support. Network futures run on the existing Tokio runtime from F03 blocking jobs.
Cancellation interrupts requests/body reads; extraction/checksum loops also check it.
There is no private runtime, extra worker pool, shell or automatic package-manager
execution. Manual instructions stay data.

ZIP, TAR, TGZ/TAR.GZ, GZIP binary and raw packages are staged, bounded, checksum
checked where supplied, and command-validated before touching an older install.
unpackSubdir controls command lookup and working directory. Executable bits are set
only on installed package files, with nested command lookup where needed. Unsafe
paths, links, special entries, oversized metadata/files and duplicate/reserved files
fail explicitly. A root lock serializes updates; failed/cancelled preparation cleans
staging. Complete replacement retains the previous directory, rolls back failure,
and reports its location. Explicit uninstall preserves the root and unrelated files.

Alt+4 opens settings. Keys and mouse select/scroll servers, refresh, install/update/
reinstall, remove, start/stop/restart and cancel. Installation/version/running states
are separate and remain readable in the normal sidebar width. Work and progress
are tagged and acknowledged; cancellation keeps the operation busy until its reply.
Owner/workspace changes reject stale results, drain accepted work and stop registered
services. The welcome screen cannot intercept focused settings' Enter action.
P02 registers the real process callback; until present, lifecycle requests explicitly
report unavailable and never claim a running server.
