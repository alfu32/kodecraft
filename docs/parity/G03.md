# G03 — Diff views and restoring worktree chunks

Task: G03. Status: done.
Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.

Read DiffView.kt, SideBySideDiffView.kt and Main's show/clear/restore/tab-change
handlers. The active main-pane comparison now uses `kode_git::diff::DiffPlan` and
`kode_tui::panels::git::diff`. Source diffs used JGit HistogramDiff, then recomputed
the edits when restoring an ordinal. Rust retains one immutable native hunk set
with source line/byte ranges for both display and restore.

Prepared side-by-side rows include original line numbers, inserted/deleted/modified
and context styles, synchronized wrapping/scrolling and per-side color handling.
`c` toggles context, `v` switches to unified +/- presentation, with corresponding
mouse footer controls. Missing final LF is explicit. Empty comparisons report no
changes; binary/oversized/symlink/submodule comparisons show typed notices. Normal
unstaged, staged and historical comparisons have distinct labels/restore policy.

The visible projection is a virtual read-only Historical host using the common
editor. It retains selection, copy, find, scrolling, keyboard/mouse navigation,
search priority and core mutation guards. Copy returns displayed text, including
line numbers/markers; it never changes physical source bytes. Source-point maps
preserve selection/viewport through reflow. Generation/request gates reject late
layout/read work, including same-width replacement and rapid resize. Preparation
runs in cancellable F03 workers; paint has no native Git or filesystem calls.

Restore uses the exact captured hunk bytes, checks disk identity/old index/new
worktree captures and open document revision, refuses dirty text/binary buffers and
application session/cache paths, reserves the file against saves/actions, and holds
the actual index lock. E04 guarded atomic save preserves unselected bytes, BOM,
CRLF and final-newline state. An old preview, changed index, external lock or leaf
symlink replacement cannot write. Historical/staged/unsupported content cannot
restore. Missing deleted files can be recreated; removing all newly added text
leaves an empty regular file, matching the source action.

Successful restoration reloads only clean captures of that file, refreshes Git and
native indexing and retains preview/sidebar focus. Newer typing remains in memory
with its old disk baseline. Leaving Git or opening a normal file clears the preview
and rejects late results; the ordinary viewer returns. Accepted restore jobs are
critical and drain before quit, including an immediate quit after submission.

Algorithm evidence: a real source-compatible JGit 7.4.0.202509020913-r Java oracle
was executed using the cached pinned jar, without modifying the reference checkout.
For old `a,b,c,a,b,c` and new `a,c,b,a,c,b` (LF lines), HistogramDiff chooses middle
ranges `(3..3,2..3),(4..5,4..4)` while libgit2 chooses
`(3..4,2..2),(5..5,3..4)`. Both scripts describe the same source transition.
`fixtures/git/diff-algorithm.json` records the complete counterexample and native
tests pin it alongside three matching repeated/reordered-line cases. No claim of
identical chunk grouping is made; displayed and restored grouping is identical.
