# R09 — Extended authentication protocols

Status: done

User-authorized extension M002, 2026-10-16, based on docs/UAT/img_3.png.
R08 prerequisite is complete. Frozen Kotlin baseline remains unchanged.
Qualified environment: Linux x86_64, Rust/Cargo 1.99.0 stable; synthetic fixtures
only. No vendor account credentials, developer sessions or remote services used.

The shared scheme catalog exposes all eleven pictured choices in the model and
actual request form: No Auth, API Key, Bearer, Basic, Digest, OAuth 1.0, OAuth 2.0,
Hawk, AWS Signature, NTLM and Akamai EdgeGrid. Collection/folder/request
inheritance and arbitrary Postman fields survive selection/edit/export. Credential
masking covers both rows and value dialogs. Resolved execution parameters are
bounded, variable-resolved, non-serializable and redact credentials from Debug.

The HTTP transport signs its final headers and materialized body bytes. OAuth 1.0
uses HMAC-SHA1 with RFC 5849 escaping and encoded duplicate query/form ordering;
OAuth 2.0 accepts a supplied token and header prefix. Hawk SHA256/384/512 includes
the actual content-type/payload hash. AWS uses the official SigV4 signer, with S3
path/checksum settings. EdgeGrid follows its provider's ordered headers and POST
prefix hash. Generated time/nonces are fresh at execution, not persisted settings.

Digest uses the actual method/target/body and negotiated RFC 7616 algorithm/qop.
NTLM uses explicit username/password/domain/workstation NTLMv2 and an isolated
HTTP/1.1 client. Challenge bodies drain on the same connection under 64 KiB; closing
connections and invalid frames fail. Types, flags, offsets and UTF-16 field lengths
are checked before calling the selected parser. At most one retry follows a 401;
other failures never implicitly replay a request. Cancellation/deadlines include
the entire exchange. HTTP/SSE share the challenge path. Logical pre-send preview
labels dynamically generated Authorization rather than presenting an unsigned
request as final.

Supported boundaries are visible: advanced-auth redirects return their 3xx for
explicit review, with form text and response normalization notice; credentials
never automatically follow them. Static signers use actual GET/empty-body
WebSocket handshake semantics. Digest/NTLM WebSocket upgrade negotiation has an
explicit error before connecting. NTLM is a manual NTLMv2 client, without OS
integrated logon/Kerberos/channel-binding claims. OAuth acquisition is R10.
