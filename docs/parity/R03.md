# R03 — Postman and OpenAPI import/export

Status: done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`, clean.
Read all of `RestOpenApiImporter.kt`, the import/export methods of
`RestWorkspaceModel.kt` and both original `RestModelTest` OpenAPI file cases.
R01 and its lossless collection/model fixtures are implemented and qualified.

Implemented `kode-rest/src/import/{mod,parse,yaml,files,openapi}.rs` and
`openapi/{operation,schema,auth}.rs`, four paired JSON/YAML fixtures and 17 focused
integration cases. Public contracts: `Import::{from_document,apply}`, `parse`,
`read_file`, `export_file`, structured `Notice` values and atomic
`Workspace::append_items`. The R02 resolver rejects generated items marked
`x-kode-import-incomplete` before materialization or networking.

- Postman root import replaces the collection. Nested import retains the whole
  collection as a folder, including inherited variables/auth/headers, scripts,
  disabled rows, saved examples, IDs and arbitrary fields. Existing `name`
  extensions are preserved too. Candidate validation precedes workspace publication;
  failure preserves selection, revision and collection data.
- Swagger 2.0 and OpenAPI 3.x preserve operation order, tag grouping, fallback
  names, path variables, query/header parameters, inherited parameters with
  operation overrides, first server/media selection, server variable defaults,
  path/operation server overrides, examples and simple schema samples. JSON
  strings remain quoted payloads; `+json` and `+xml` select the proper language.
  Swagger form text fields become URL-encoded or multipart rows.
- Local JSON-pointer references resolve parameters, request bodies, schemas,
  examples and security schemes, with escaped names and cycle/depth checks.
  Basic, bearer and header/query API-key authentication map to explicit credential
  placeholders. Unsecured operations use noauth even inside an authenticated
  destination folder. No credentials or token acquisition are invented.
- The original importer did **not** resolve references, map security schemes,
  evaluate composition or implement special OpenAPI 3.1 schema behavior. Native
  conversion adds local references and supported auth. The complete source
  document and notices remain under `x-kode-openapi`; operation pointers identify
  generated requests. External references/examples are never fetched. Unsupported
  security combinations, auth, reference siblings, schema composition/dynamic
  validation, relative servers and parameter/body encodings have explicit notices.
  Affected runnable requests are marked incomplete. Callbacks/webhooks/response
  links remain source metadata, with a notice. Alternative servers/media/security
  choices are retained and first-choice selection is reported.
- The maintained parser is pinned **serde-saphyr 2.0.0**, deserialize feature only,
  after inspecting its actual API/source and [primary documentation](https://docs.rs/serde-saphyr/2.0.0/serde_saphyr/).
  Filesystem include/property features are disabled. Duplicate YAML map keys,
  unsupported tags and multiple documents fail. Budgets cap parser depth/events,
  nodes, scalar bytes, anchors and alias replay. Direct generic deserialization
  rounded large integers during qualification; the final adapter uses source
  spans to retain exact decimal JSON numbers, including aliases and decimal
  fractions. Other numeric syntaxes require an exact integer conversion or fail.
- Worker file I/O accepts regular UTF-8 files (including BOM), checks cancellation
  and changes during reading, and reports file/JSON-pointer or line/column errors
  without echoing document values. Imports, converted output and exports are
  limited to 16 MiB, 500,000 JSON values and 96 JSON levels, in addition to the
  model's tree limits. A nested destination that exceeds those limits fails
  atomically. These are API bounds, not a hard process RSS guarantee.
- Export accepts only collection data. Saved response examples remain intact;
  runtime responses/cookies have no export-model fields. It creates chosen parent
  directories and uses native guarded atomic writes: existing targets require
  their expected disk identity; external changes are not overwritten. Pretty
  serialization has a bounded output writer, and cancellation before save prevents
  creation. Export stays Postman v2.1; no reverse OpenAPI generation is claimed.
