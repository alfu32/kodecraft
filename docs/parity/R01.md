# R01 — Lossless REST collection and environment model

Status: done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`, clean.
Read `RestModels.kt`, `RestWorkspaceModel.kt`, `RestEnvironmentCodec.kt` and the
complete original `RestModelTest`. F02 contracts are implemented.

Implemented `kode-rest/src/model/{mod,path,environment,workspace}.rs`, a checked-in
Postman fixture and model tests. `Workspace` keeps the complete JSON collection
alongside typed extensible session/environment/UI data. Arcs provide immutable
captures; mutations preserve unknown fields and existing data. No runtime response,
cookie or execution handle is part of the persisted model. Saved Postman examples
and scripts are retained as JSON; script execution is not introduced.

Implemented path addressing/tree traversal, root/folder/request rename, create,
delete, duplicate, move, move-up/down, UI selection/height/pretty preferences,
session restore/snapshot and collection value import/export. Copies regenerate
request IDs with UUID v4 while moves retain them. Environments support create,
rename, copy, activate/deactivate, remove, enabled variable lookup and lossless
metadata/structured-value edits. The original escaped line codec is ported.

Intentional corrections to source behavior:

- Malformed paths fail instead of silently dropping invalid components.
- Removing a source before a later sibling destination rebases that destination;
  same-parent/clamped moves return the actual inserted index.
- Insert/delete/move/duplicate preserve selected node identity, including nested
  selections whose ancestor array position shifts.
- Duplicate retains nonobject children that the source's `mapNotNull` could drop.
- Environment text edits retain enabled/type/description/secret/extra metadata by
  key/occurrence. An unchanged structured value stays structured rather than
  becoming a string merely from opening/saving the text representation.

Dependencies: Serde/serde_json preserve-order/arbitrary-precision/Arc features,
IndexMap and UUID 1.28.0 v4. UUID was already resolved transitively; its selected
local source/Cargo features were checked before enabling OS-generated v4 IDs.
Public ownership and mutation contracts are in `docs/migration/CONTRACTS.md`.

Qualification on stable Rust/Cargo 1.99.0, Linux x86_64:

- `cargo test -p kode-rest`: **12 tests passed**. The original environment codec /
  active management, item CRUD/move and unknown-field preservation cases are
  translated. The original two OpenAPI JSON/YAML cases are owned by R03 and remain
  pending there, rather than being simulated in this model.
- Additional tests cover nested move/selection repair, same-parent ordering,
  clamped and invalid indices, malformed paths, fresh IDs, unknown nonobject
  children, scripts/examples/disabled rows/object values, extra fields at each
  typed level, arbitrary-precision numbers, immutable captures, transactional
  failures, metadata retention and explicit tree bounds.
- `fixtures/rest/model/preserved.postman.json` roundtrips through edit/export and
  typed project serialization with exact JSON data except the intended rename.
- All-target `cargo clippy -p kode-rest --all-targets -- -D warnings`, formatting
  and diff checks pass. `cargo check --workspace` passes.

The line codec deliberately retains the source's trimming/comment syntax; use
structured edits for multiline values or significant edge whitespace. Model tree
bounds are 100,000 nodes / 64 levels. File parsing/writing and OpenAPI are R03;
network execution and real UI/persistence remain R04–R08. This does not mark the
REST feature or the full migration complete.
