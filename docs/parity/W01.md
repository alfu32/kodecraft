# W01 — Source roots, exclusions and project scanning

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable, Linux x86_64.

Project configuration selects only existing `src`, `lib`, `include` folders for
new projects. Saved empty roots stay empty. Relative/absolute paths resolve inside
the canonical project boundary; source/exclusion editing validates directories,
files and root exclusions. Effective roots deduplicate canonical/overlapping paths.
Scanning traverses configured roots and necessary ancestors, never unrelated trees.

ignore 0.4.33 supplies traversal and Gitignore syntax. Standard filters are explicitly
disabled: cached project-local root/nested matchers implement ordered rules, scoped
anchoring, negation and hidden-entry whitelisting. Ancestor exclusions prune children;
user file/folder exclusions remain separate and cannot be re-included by nested
ignore files. No parent/global `.ignore`, Git global or `.git/info/exclude` configuration
silently changes indexing. Cached bounded folder queries implement the original
four folder statuses; tree/search browsing remains independently configured.

Git/Kode metadata and root build/target outputs are excluded. Regular file symlinks
inside the project may resolve to one canonical file identity; outside targets,
directory links/cycles, sockets/devices/pipes never become index files. Hidden entries
need explicit inclusion. Unreadable directories and traversal/ignore errors remain
visible warnings, bounded at 128 plus an omitted count. Cancellable 128-file batches
carry separate scan progress. The collector stages a new list and keeps the previous
publication on cancellation, failure, incomplete scans or missing batches. Exact
workspace/request identity rejects results after workspace switches.

Intentional corrections: Git's nested-relative anchoring, ignored-ancestor and escape
rules replace the source's simplified glob matcher. Exact metadata/build components
avoid falsely excluding `buildSrc` or an explicitly included `.github`. Canonical
boundaries prevent symlinks introducing files outside the configured project.
Partial/unreadable scans cannot erase a good previous file list.

Seven tests replay original scanner/folder-status fixtures and cover defaults versus
saved-empty configuration, overlap/absolute roots, editing exclusions, root/nested
negation and anchoring, hidden includes, metadata/prefix boundaries, parent-ignore
isolation, unreadable folders, canonical aliases/loops/outside links, cancellation,
staged/old-generation publication and actual bounded-worker batches/final summary.
Passed: all 126 workspace tests; workspace check; format check; workspace all-target
Clippy with warnings denied. Final cfg-only portability cleanup preserves Linux behavior.
Native Windows hidden-attribute qualification remains Z04.

Parsing/traversal APIs were checked against [ignore WalkBuilder](https://docs.rs/ignore/0.4.33/ignore/struct.WalkBuilder.html),
[Gitignore matcher](https://docs.rs/ignore/0.4.33/ignore/gitignore/struct.Gitignore.html) and
[Git's ignore rules](https://git-scm.com/docs/gitignore), as well as Kotlin scanner,
folder-status tests and Main's configuration helpers. Next ready task: W02.
