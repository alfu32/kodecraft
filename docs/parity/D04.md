## Implemented boundary

Java `connections/ConnectionService.java` implements test/open/close/context and
transaction commands through the selected driver's direct `Driver.connect`.
Its connection owns the loader lease and context classloader until confirmed
close. One serialized platform worker per datasource owns all ordinary JDBC
objects and operations; different consoles share that connection and transaction.
Temporary tests use separate bounded workers, report H2 product/driver versions
and latency, and close their connection before replying. A temporary test never
replaces or changes the live datasource session.

Native `connections.rs` and `connections/operations.rs` expose inert construction,
snapshots, epoch-tagged session information, typed SQL errors, temporary testing,
open/close, context, commit/rollback and explicit definition-change invalidation.
Java starts only for an explicit database operation. Driver inspection honors
the D03 selected version/classpath without implicit installation. Credentials
resolve from one bounded private snapshot on a bounded blocking worker, then
enter only ephemeral connection properties. Empty reference sets perform no I/O.
Property precedence is public properties, private property references, nonblank
username, then password override or private password reference. Missing references
are visible failures; neither test nor connect modifies the credential file.

SQL errors keep bounded redacted messages, SQLSTATE, vendor code and chained
exceptions, including cyclic-chain protection. Native Debug omits message bodies
and connection metadata. Driver output cannot enter protocol stdout; raw stderr
remains unavailable through native diagnostics. Secrets are not promised to be
zeroized by either runtime.

## Transactions, context and lifecycle

Catalog/schema setters verify actual results. Omitted context fields remain
unchanged; explicit null restores login defaults. Read-only is a JDBC hint and
an ignored setter is reported as unsupported rather than claimed as enforcement.
Autocommit changes last because enabling it can commit pending work. Driver
failures preserve actual context and invalidate revision assumptions; getter
failure is an explicit unknown context. Manual-transaction SQL errors
conservatively require rollback before commit/autocommit. Commit and rollback
execute on the same worker as statements and metadata.

Connection/context state has a helper epoch, connection ID, context revision and
monotonic owner snapshot revision. Independently delivered replies cannot restore
older native state. Saving even an equal definition requires
`Connections.definition_changed`: a private value may have changed under an
unchanged credential reference. Reopening the same live definition returns the
shared current session; changing it requires explicit disconnect.

Disconnect uses reserved control capacity and a reserved owner queue slot, rejects
queued work before execution and interrupts/requests independent JDBC abort for
busy work. Actual close stays on the owner. A close reply follows registry removal,
so immediate reconnect cannot see the retired session. An unconfirmed close
retains its loader and requires explicit helper restart. A driver error after
confirmed close still returns a visible SQL error with `data.closed: true`.

Unique attempt IDs and bounded cancellation tombstones prevent priority close
from overtaking ordinary open dispatch and leaving a hidden late connection.
Cancellation by attempt cannot close a newer session. Native dropped/canceled
open waits route that cleanup and tracked shutdown joins it. Failure/timeout
after submission retains uncertainty; abandoned transaction waits require
explicit disconnect before further commands. Helper death invalidates connection
IDs and marks unknown outcomes without sending rollback, restarting or replaying.
Workspace shutdown cancels/drains native operations and stops/reaps the helper.

Ordinary RPC final replies now use independent virtual tasks bounded by retained
request permits. Completing a JDBC future cannot block its owner behind a full
output queue. Control replies retain priority; a query final still follows its
already emitted events in the ordinary FIFO. Connection owner fields are published
before starting their threads; concurrent-open regression covers that startup race.

## Acceptance evidence

Qualified on stable Rust/Cargo **1.99.0**, Java **21.0.9**, Maven **3.9.16**, Linux
x86_64. Synthetic temporary fixtures only; no production database or credential
file was accessed.

- `bash scripts/test-jdbc-bridge.sh`: **43 Java tests passed** and **22 Rust
  integration tests passed** (13 bridge, 5 connections, 4 installer), including
  all three opt-in actual shaded-helper tests.
- Java connection tests cover actual H2 metadata/latency/authentication and bad
  URLs; insert/update/rollback, commit and autocommit; shared-console identity;
  context failure/reset/ignored read-only; failed transactions and bounded cyclic
  SQL chains; concurrent owner startup and immediate reconnect; busy disconnect,
  queued-work rejection and owner identity; priority cancel before open; failed
  and confirmed-with-warning close. The RPC saturation test proves a connection
  owner remains available while ordinary responses wait for pipe capacity.
- Native tests cover inert construction/reads/shutdown, private reference batches
  and property precedence, missing credentials, shared current context, definition
  changes, cancellation/drop cleanup, and crash during a pending commit. The
  crash trace contains exactly one commit and no rollback/replay; explicit restart
  and connect use new helper/connection IDs. Actual Java/H2 exercises native
  test/open/context/reset/commit/rollback/authentication/disconnect/reconnect.
- `cargo test --workspace`: **424 passed / 3 opt-in ignored**; all three opt-in
  tests passed separately above. An unrelated LSP fixture readiness race found
  under load now waits for a complete numeric PID before cancellation/reading,
  instead of merely observing the newly created empty file. All eight LSP client
  tests passed again with the final readiness checks.
- `cargo check --workspace`, database/TUI clippy with `--all-targets -- -D warnings`,
  formatting and diff checks pass. `cargo build -p kode` passes;
  `python3 scripts/test-database-models-terminal.py` verifies actual terminal
  startup without Java, unchanged source, untouched DB paths and restored terminal
  modes ([PTY evidence](D01-pty.json)).
- `python3 scripts/database-catalog.py --check`: all **59 driver definitions** and
  the exact URL catalog still match the source. Protocol schemas/operation fixtures,
  README and shared contracts document D04's methods, limits and lifecycle.

Bounds: 32 live datasource owners, 16 queued ordinary jobs per owner plus close;
4 temporary-test workers/16 queued tests; 2 abort workers/32 queued aborts;
64 native operations, 4 credential readers, 4,096 tracked datasource records and
4,096 canceled attempt tombstones per helper epoch. Native request waits are
60 seconds; close confirmation waits five seconds. These are resource/deadline
bounds, not claims that arbitrary vendor JDBC calls are interruptible. A driver
that ignores cancellation/abort may require explicit retry of close or helper
restart; closing/killing a helper never claims transaction rollback.

D05 owns query streaming, independent statement cancellation and its native
execution client; D06 metadata, D07 dialogs/application composition and D08 SQL
console/result UI remain unfinished. Every JDBC object in those services must
use the D04 owner. Vendor databases beyond deterministic H2/fake-driver fixtures
and non-Linux runtime qualification remain D09/Z04. The migration is not complete.
