# U04 — Multiple cursors and selections

Status: done

B004 is implemented in the shared text editor. Alt+left-click adds a cursor or
removes an existing cursor and its selection, retaining at least one valid
primary. Alt+drag adds a selection over the retained set, including reverse
selection, outside release and auto-scroll. Plain click resets the set; Escape
keeps its primary. Ctrl+Shift+Up/Down adds a cursor at the reached visual row,
using the same wrap, tab, Unicode-escape and fold map as drawing/hit testing.
An already present cursor is promoted without losing its selection direction.

Alt+Enter in file find selects every current nonempty occurrence and returns to
editing. This preserves the existing bounded regex worker and current query,
workspace/document/revision checks. Pending selection cannot survive a changed
query, focus loss or closing search. Ctrl+Enter retains its existing find-all
highlight behavior and focused-child priority over SQL/REST execution.

`CaretState` keeps a primary selection and secondary selections. Normalization
validates UTF-8 byte boundaries, merges overlap/duplicate or contained carets,
retains the primary direction and leaves adjacent nonempty ranges independent.
Typing, tab, newline, deletion, bracketed and native paste operate on this set in
one original-snapshot transaction and revision. Each newline uses its cursor's
original indentation. Collision after deletion merges the resulting carets.
One undo/redo restores the whole normalized selection set and exact text.

Copy/cut joins nonempty selections in source order with LF separators. Paste
repeats the complete text at every selection, including multiline clipboard text.
Read-only guards cover every mutation path. Native paste proofs include all
selections plus request/document/revision/focus. Completion and navigation also
capture the full set, so a secondary-only change rejects late results. Provider
completions keep their authoritative primary replacement range and remap the
other selections; undo restores the previous set. Search replacement explicitly
owns its result set and retains the previous multi-selection for undo.

All selections and cursors paint with the existing selection/cursor styles,
including empty lines and EOF; only the primary supplies the real terminal cursor
and scrolling anchor. Stale drags are disposed after another view changes the
document. History v1 stores optional secondary selections, defaults old JSON to
single selection and validates all imported coordinates before committing.
File restart retains them; stale-file restoration remaps them through UTF-16
positions while preserving dirty recovery. SQL, REST, environment and search
preview hosts share the same reducer and history; owner execution uses the primary.

Validation uses stable Rust 1.99.0 on Linux x86_64. The selected core, workspace
and TUI suites pass **349 tests**. Their four opt-in Java/H2 cases are additionally
enabled in the database_app and jdbc_qualification suites: **13 tests pass**,
including all four real helper cases. Those exercise SQL/transaction/result
focus, actual helper crash, workspace disposal, child cleanup and native editor
availability. Format, affected all-target Clippy with warnings denied and CLI
build pass.

The new cases include:

- Eleven core multi-selection tests: independent stream oracle for every triple
  of cursor positions in documents up to seven bytes, Unicode/reverse/overlapping/
  adjacent ranges, EOF/empty/duplicate cursors, paste/delete/indentation, atomic
  rejection, history import/export, search replacement and primary promotion.
- Fifteen editor-input cases, including Alt+click/drag, visual rows/wraps/folds,
  Unicode boundaries, native paste proofs, source-order copy/cut, empty/read-only
  documents, stale drag disposal and primary scrolling. Renderer cases check
  every caret/selection style, empty lines, EOF and tiny clipped panes.
- Search, completion and navigation stale-result cases, plus editable
  file/project-search/SQL/REST/environment host transactions, execution ownership
  and response/raw/historical mutation guards.

Twelve actual CLI terminal cases pass, recorded in [U04-pty.json](U04-pty.json). The
fixture runs at 100×34 and 60×24 and checks file find-all, typing/paste, undo/redo,
vertical cursors, physical saves, UTF-8 Alt+click/toggle/drag, cursor-set restart,
source-order copy/cut and real clipboard-worker paste, SQL owned drafts and REST
body/header edits. It also selects raw-request occurrences and verifies that a
mutation attempt is rejected and never persisted. Fixtures require no Java or
external HTTP server. Every case checks clean exit and terminal restoration.
The CI distribution workflow runs the fixture against its release binary and
uploads the generated report; a remote CI run is not claimed here.
