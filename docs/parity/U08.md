# U08 — Project-relative paths in the open-file list

Status: done

B005 is implemented in Files → Recent. Physical entries default to their paths
relative to the project root, preserving directory context for equal basenames.
The project root itself is shown as `.`. Outside-root entries remain absolute;
virtual Git/SQL/REST documents retain their existing labels and owner lists.
Control/wide characters use the existing safe terminal display mapping.

Click `[paths:rel]` / `[paths:full]` in the Recent header or press **P** with the
Files panel focused to toggle full paths. Generated Help includes the binding.
The per-project `fullFilePaths` session preference defaults to false for older
sessions and survives autosave, project switching and restart. It flows through
the existing sequenced capture worker, so changing it during a pending capture
cannot replace newer UI state with an older snapshot.

Labels are derived only when rendering. Recent entries, selected/active paths,
open/remove commands, document IDs and save targets retain physical identity.
Toggling does not open another document, change selection or reset scroll.

Validation: **70 tests pass** across kode-workspace (34), workspace_panels (10),
workspace_bootstrap (6) and app_runtime (20). New cases cover equal basenames,
mouse target identity, root/outside/Unicode labels, zero/tiny widths, saving to
the selected duplicate, project-scoped preference restoration and virtual owners.
Affected all-target clippy with `-D warnings`, debug CLI build and format pass.

[Four real PTY cases](U08-pty.json), at 100×30 and 60×30, exercise keyboard/mouse
toggles, both equal-basename files, outside-root display, correct physical save,
restart preference and active-file restoration. File bytes, relative persisted
paths, clean exit and exact terminal mode restoration are checked. The JVM is
absent from these fixtures; no user workspace/session is opened.
