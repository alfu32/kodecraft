`jdbc-bridge/drivers/` now supplies resolution, installation, inspection and loader
leases. Apache Maven Resolver **2.0.23** is pinned using its
[Maven 3 supplier artifact](https://maven.apache.org/resolver/maven-resolver-supplier-mvn3/dependency-info.html).
It handles real parent POMs, imported dependency management/BOMs, runtime scopes,
optional/provided/test exclusions, classifiers and dependency mediation. The driver
is a dependency under a virtual application root, giving the library's optional
selector the correct depth. Missing/invalid required POMs fail visibly rather than
silently claiming a complete runtime graph.

The repository is the configured custom root or Maven Central. As in the source,
POM-declared additional repositories are not implicitly consulted. There is no
Maven CLI invocation, user Maven settings/credential lookup or partial XML parser
at helper runtime. Session interpolation gets only ordinary Java/OS activation
properties, not arbitrary environment/user properties. Explicit versions are
honored; when absent, Resolver supplies version metadata and the frozen source's
stable filtering/numeric/qualifier ordering chooses the version. The result is
pinned in the install pointer/manifest and reused offline.

Two resolver workers with eight queued jobs are independent from RPC input,
ordinary dispatch and control dispatch. A resolution ID addresses cancellation;
its acknowledgement does not finish the original operation. Transfer progress is
throttled, checks cancellation and bounds artifacts/bytes/attempts. Vendor HTTP
downloads have independent cancellation/response closure and a deadline. No URL
is invented for page-only vendor entries: a typed manual-JAR result preserves the
vendor page and creates no install root.

Local sources support every selected JAR using the platform path separator.
Missing parts of a new multi-JAR classpath fail visibly. Legacy provider/version
directories and Java-properties version pins are read without modifying their
files. A missing legacy version pin never combines arbitrary version directories.
Source H2 **2.2.224** remains bundled/visible, preserving the original application's
default H2 behavior; installed classpaths can select other versions independently.
The helper does not substitute that bundle for a different explicitly selected
version. The intentionally old bundled version preserves source/file compatibility;
this report does not call it the latest H2 release.

## Publication and reuse

Every resolution uses a private temporary work directory under the selected
plugin root. JARs are copied/hashed into an immutable install, checked as JARs,
flushed, and published by atomic directory rename. A per-provider OS lock protects
the small atomic selection pointer. A complete manifest contains source/version,
ordered relative artifact paths, SHA-256 digests, sizes and a classpath digest.
Existing/in-use installs and original local/legacy files are never overwritten or
deleted. Publication failures leave the prior pointer intact; cancelled/failed
normal jobs clean their own work tree. Late cancellation cannot relabel an already
published success as rolled back. Known pre-publication failures explicitly mark
that no install was published, avoiding a misleading uncertain-outcome UI.

Provider identity excludes aliases/display names/class discovery. Coordinate,
repository, classifier and source identity separate different installs; a version
family key recognizes a previously selected latest version once the connection
dialog pins it explicitly. A trailing repository slash does not break that reuse.
Identical ordered JAR bytes can reuse content even with different original names;
returned paths always name the actually published files. Every cache reuse verifies
its manifest and JAR hashes. Local source changes cause a fresh immutable install;
installed copies remain usable after their original import files are removed.

`driver.inspect` supports explicit paths or a complete spec. Spec lookup prefers
configured local paths, validated installs, legacy version directories, then the
matching visible H2 fallback. It never downloads or creates an install root.
Maven/vendor downloads follow the selected repository type; configured local paths
remain an inspection/loading override. Native `drivers::Installer` provides typed
install/inspection state, explicit helper environment paths, progress watches,
version-aware lookup and helper-epoch-tagged loader information.

## Loader ownership and UI boundary

URLClassLoader parents are the platform loader, keeping vendor dependencies apart
from helper libraries and other providers. The cache includes provider ID, ordered
byte digest and physical locations; differing versions of one provider can coexist,
including while their connection leases remain active. Matching service classes
are preferred; explicit-class discovery and the source's usable service-provider
fallback remain supported. The frozen Derby Embedded class name, for example,
selects its modern service provider without rewriting the saved definition.
Partial service load failures report sanitized error types.

Each connection lease retains its intended Driver instance/context loader for
direct Driver.connect dispatch in D04. Closing/evicting a loader waits for all its
leases; a bounded cache evicts only unused entries. A small known helper class is
defined inside each child loader so DriverManager's caller-visibility rule permits
deregistering that loader's own static registrations. Closing one loader cannot
deregister another provider/version. Wrapped native linkage errors explicitly
require helper restart; closing Java loaders does not claim native libraries unload.

Rust notification subscriptions route driver progress independently from query
data, share a byte bound and coalesce only progress by resolution ID. Query overflow
remains an explicit disconnect with received data retained. A dropped install wait
routes driver.cancel. Ordinary cancellation waits for the original final result;
helper crash/timeout retains uncertainty and never replays an operation.

The `driver_install` modal is an inert main-thread reducer with the shared theme,
bounded layout, progress/indeterminate bar, cancellation and final acknowledgement.
It emits one cancel action, stays open through cancellation, accepts only the exact
workspace/request completion and preserves a successful publication that wins a
late cancel. Unknown outcomes instruct refresh rather than claiming cancellation.
It runs no filesystem/network/Java work from paint/input. D07 owns its application
composition with complete connection/driver dialogs; no database tab is claimed here.

a clean local classpath after helper restart requires explicit action. Abrupt process termination can leave ignored

publication is not a cross-file filesystem transaction or platform crash-durability
claim. Linux is the qualified host; Windows/macOS native execution remains D09/Z04.
