# V03 — Image decoding and colored cell modes

Status: done  
Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`  
Compiler: stable `rustc 1.99.0 (b940084d7 2026-09-28)`.

The image viewer now decodes files in workers and paints portable Ratatui cells.
Mode cycling preserves Quart → Demi → Braille → Bixel → Quart; Demi/Bixel share
the source's half-block sampling. Width uses the source's step-four keys and
release-committed slider. The default view retains the source's single visible
Width control; `[more]`/M exposes the source's previously hidden Gray/Contrast
controls. Enter also cycles mode. Mouse coordinates are absolute, capture ends
outside the pane or on focus loss, and repaint does not perform decoding/sampling.

Aspect height truncates source-height × width / source-width / 2 with minimum four
rows. Only visible rows allocate cells, with full-height scaling retained. Latest
worker tags reject outdated resize/mode results, detached views and generations.
Image recents/active origin survive restart; view switching preserves the shared
text registry and critical saves. Decoder failures retain their error and open
raw bytes in hex. User MIME overrides keep precedence over new decoder defaults.

Changed paths: `kode-platform/src/images/`, `kode-tui/src/viewers/image.rs`, small
workspace MIME registration and application routing/state/worker changes, original
image fixtures/oracle scripts, image/platform/view/runtime tests. Public contracts:
immutable `DecodedImage`, bounded `CellOptions`/`CellImage`, `ImageSettings`,
`ImageJob`, worker `PreparedImage` and `PreparedViewer::Image`.

Qualified decoder matrix:

| Format | Evidence / scope |
|---|---|
| PNG | RGBA checker with retained hidden RGB under transparent alpha |
| BMP | Original 24-bit bottom-up checker |
| GIF | Original one-frame indexed red pixel; display uses first frame |
| TGA | Original 32-bit top-origin checker |
| DDS | DXT1, DXT3, DXT4, DXT5; explicit partial-alpha DXT4 unpremultiplication |
| PSD | 8-bit RGB/RGBA or single-channel grayscale composites, raw/PackBits; unrelated sections ignored after bounds validation |
| KRA | Bounded `mergedimage.png` ZIP preview; no extraction or layer reconstruction needed for display |
| SVG | Self-contained geometry, system fonts and bounded embedded raster references; external/unavailable references report an error |
| JPEG/WebP | Additional effective source MIME catalog formats; encoded-pixel regressions |

The source's actual Korim 4.0.10 decoder source was also audited from its cached
sources JAR: DDS includes DXT4, PSD reads the composite while ignoring its layers,
and KRA displays `mergedimage.png`. The image crate's DDS decoder needs a DXT4
FourCC adapter. PSD depth/color modes are explicitly checked instead of repeating
the source's incorrect assumption that every channel is 8-bit RGB. Other PSD
modes/depths/compressions, PSB, SVGZ and unavailable SVG references report their
limitations and allow hex inspection; this matrix does not claim arbitrary image
subformat support. Explicit `.svg` → text resource mapping remains source-compatible;
SVG decoding is qualified directly and for image-classified SVG signatures.

Limits: encoded files/previews 64 MiB, SVG input 4 MiB, 16,384 per dimension,
16 megapixels per decoded image, 128 MiB raster decoder allocation request,
4,096 KRA entries checked before ZIP indexing, one million output cells. Pixel
and input bounds are enforced; third-party decoder allocation limits are also
requested. `image::Limits::max_alloc` is a best-effort decoder limit, not a hard
process RSS guarantee. Subordinate SVG raster dimensions share a pixel budget.
Malformed decoder panics become typed worker errors. The active viewer retains
one decoded image; resampling clones its immutable pixel Arc.
