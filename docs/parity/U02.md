# U02 — Readable database errors and diagnostics

Status: done

B003 is implemented and qualified on the final build.
Database/SQL status remains concise; F4 and visible Details controls open an
immutable, wrapped diagnostic snapshot. Connection tests, connection/configuration
and helper failures, driver installation, metadata errors and SQL results use the
same read-only modal. Details include their operation/datasource/request or SQL
console/execution identity. F4 follows focus between the explorer and SQL view.

Arrow keys, PageUp/PageDown, Home/End and mouse wheel navigate the full text.
Copy/Ctrl+C copies the complete redacted snapshot, including its identity header;
Close/Escape restores focus. A parent operation may finish while details remain
open, without returning focus to a disposed form. Opening details releases any
previous pointer capture. Errors do not open a modal or take focus automatically.
SQL's Messages tab also wraps and scrolls complete lines. Empty, resized and
single-cell layouts remain bounded; terminal-control/unrenderable scalars use the
existing editor display escapes.

The Java helper preserves newlines and up to 65,536 Unicode scalars per message,
with an explicit truncation marker beyond that bound. At most sixteen additional
JDBC/causal entries retain SQLSTATE/vendor codes, with cycle detection. Configured
secrets and sensitive assignments are redacted first; other terminal controls are
sanitized. Native query validation admits the matching UTF-8 bound and rejects
oversized payloads. The application no longer truncates SQL messages at 2,048
characters or flattens their line breaks/causal chain. Raw helper stderr and
unrecognized remote payloads remain private. Details are not session artifacts;
copying is an explicit user action.

Evidence:

- `bash scripts/test-jdbc-bridge.sh`: **64 Java, 48 native backend and 32 application
  tests passed**, including the normally ignored real Java/H2 qualification. The
  actual invalid-SQL application test opens F4, checks the missing-table error and
  SQLSTATE, copies it, restores editor focus, then verifies F4 belongs to the
  focused explorer when a SQL console remains open.
- Java tests retain the useful tail beyond the previous 2,048-character limit,
  preserve multiline text and JDBC/TLS causes, redact synthetic passwords/tokens,
  detect cycles and mark oversized messages explicitly.
- Native preview tests retain a >8 KiB failure through the actual query-final
  accumulator and reject a payload beyond the documented maximum.
- UI tests reach long error tails at **60/100 columns**, retain SQLSTATE/vendor
  and causal messages, copy complete text, preserve connection form values and
  restore focus. Dialog navigation, mouse scrolling, resize/tiny bounds and
  existing informational panels/widgets are covered.
- [Two actual CLI PTYs](U02-pty.json), generated by
  `scripts/test-database-diagnostics-terminal.py`, use an isolated compiled JDBC
  driver and the real helper. At **60/100 columns**, a temporary connection test
  fails with >10 KiB of multiline diagnostics. The user opens F4, reaches the tail,
  clicks Copy, returns to the native editor, pastes and saves the complete message.
  The saved fixture contains all 250 diagnostic repetitions, both error tails and
  both SQLSTATE/vendor pairs, with the test password redacted. No test credential

- Full `cargo test -p kode-tui` passes; its two normally ignored Java tests also
  pass in the explicit JDBC qualification run. Final default/real-Java application
  checks include parent completion/focus restoration and explorer versus SQL F4
  ownership. All seven native database unit tests pass.
- The final rebuilt CLI repeats both diagnostic PTYs successfully. All three
  existing database PTYs also pass, including no-Java recovery and edit/save.
- Affected all-target clippy with `-D warnings`, workspace all-target check,
  formatting, generated ledger, 521 locked credits and diff checks pass.

The explicit per-message/chain limits remain; the UI does not promise unbounded
exception graphs or expose unredacted third-party stderr. Synthetic fixtures never
read a developer session or credentials.
