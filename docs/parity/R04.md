Public contracts:

- `Executor::execute(ExecutionKey, PreparedRequest, CancellationToken)` is a native
  async future polled by the application scheduler. `ExecutionKey` captures the
  shared `JobTag` plus collection item ID. Constructing an executor starts no task
  and performs no I/O. Separate workspace owners have separate runtime cookie jars.
- Immutable responses retain the original prepared request, a normalized logical
  initial request, normalization notices, timestamps/duration, status, final URL,
  duplicate/raw-byte headers, Set-Cookie values, content type, capped raw body,
  received count, truncation and a typed transport/cancel/timeout outcome.
  Non-2xx status is response data, not a transport exception. Diagnostic Debug and
  error messages omit URL/header/body/cookie values.
- Request validation precedes network I/O, including manually constructed DTOs.
  Duplicate application headers are appended. Authority/framing/hop headers are
  normalized and reported; the logical preview uses the actual materialized bytes
  and initial cookies/auth. Host and Content-Length derive from URL/body. Expect
  and Upgrade are omitted with a normalization notice; no 100-continue handshake
  is claimed. Source's restricted-header regression succeeds.
- Reqwest **0.13.5** uses explicit rustls, streaming, cookies and HTTP/2 features.
  Per-request timeout covers connection, redirects and body reads; TLS bypass is
  per request, and Connection intent selects HTTP/1.1. Redirect enablement is
  honored, capped at ten hops, and HTTPS downgrade stops at the redirect response.
  Cross-origin sensitive headers are removed by the library. Standard 307 behavior
  retains POST/body when following redirects is enabled. The retry policy is
  explicitly `never`; failures/cancellation never cause replay or reconnect.
  Connections are direct, matching the baseline's absence of a proxy UI.
- The response loop continues counting bytes after its preview cap, retaining a
  bounded prefix. Cancellation, timeout and broken-body failures preserve received
  headers, body and execution identity. Dropping the selected future closes its
  response/connection work; no blocking reader thread or completion callback owns
  application state. Duration includes body capture.
- Runtime cookies use **cookie_store 0.22.1** with explicit inspection/clear.
  Domain/host-only, path boundaries/default path, Secure, HttpOnly and expiration
  matching are qualified. **psl 2.1.241** supplies a static public suffix list;
  cross-domain/public-suffix injection, insecure Secure cookies and invalid
  __Host-/__Secure- prefixes are rejected. Longest matching paths come first.
  Explicit Cookie headers override the jar. Cookies from intermediate redirects
  are retained. The jar never enters collection/session export.
- Bounds: 256 headers / 256 KiB header data; 64 MiB outgoing body and maximum
  configured response preview (default preview 10 MiB). Cookie retention is
  1,024 entries / 1 MiB including effective domain/path metadata, with a 16 KiB
  incoming cookie-header cap, oldest-update eviction and a visible rejection count.
  These are API/retention limits, not a hard process RSS guarantee. Streaming
  response totals remain accurate for received chunks even when previews truncate.

Selected library APIs/source were inspected before use, including reqwest's
redirect/sensitive-header handling, header append semantics, cookie provider,
response chunks, timeout, TLS and explicit retry disabling; cookie_store's actual
matching/insertion/removal behavior and PSL helpers were checked too. TLS fixtures
use tokio-rustls 0.26.6 / rustls 0.23.46, already locked transitively.
