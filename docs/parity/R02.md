# R02 — Variables, auth, headers, URLs and request bodies

Status: done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`, clean.
Read all 449 lines of `rest/resolve/RestResolver.kt` and the complete original
`RestResolverTest`. R01/F03 prerequisites are implemented and qualified.

Implemented `kode-rest/src/resolve/{mod,variables,types,request,body,preview}.rs`:

- Ordered scope/environment variables, disabled inheritance, recursive literal
  substitution, type/source/description/secret metadata, cycles and unresolved names.
- Effective inherited headers/auth with editability/source flags, request override
  semantics and source auth replacement ordering; noauth/basic/bearer/apikey header
  or query authentication and explicit unsupported-auth errors.
- String/structured URLs, path/query variables, UTF-8 component/form encoding,
  duplicate query fields, fragments, SSE normalization and protocol intent;
  per-request timeout, redirect and TLS preferences.
- Pure plans for raw, urlencoded, multipart text/files, file and GraphQL bodies,
  inferred/explicit Content-Type, multiple Postman `src` files and legacy file value
  fields. File I/O remains separate, bounded by the caller and cancel-aware.
- `PreparedRequest` captures complete body bytes before network work. File mutation
  after preparation cannot change those bytes. Previews show a bounded logical
  request using the same data, correct byte length/host and explicit truncation.
  Diagnostic Debug and validation/file errors omit resolved values.

Intentional corrections beyond source helpers: path substitution cannot replace
another parameter's prefix or query text; path values are percent-encoded; query
arrays preserve fragments; structured ports are retained; GraphQL JSON-text
variables become objects; unknown body modes fail rather than silently sending an
empty body. Multipart boundary headers and payload framing agree, explicit quoted
boundaries are validated, absent boundaries are supplied, and collisions fail.
The source-compatible precedence, disabled inheritance and header ordering are
covered explicitly, including fallback legacy `header` fields.

Selected local APIs were checked before use: URL 2.5.8 parsing/query serialization,
HTTP 1.5.0 method/header validation, MIME 0.3.17 parameter parsing, Base64 0.23.1,
Regex 1.13.1 and R01's IndexMap/UUID. Existing lockfile versions are pinned directly.
Multipart grammar was checked against [RFC 2046 §5.1.1](https://www.rfc-editor.org/rfc/rfc2046#section-5.1.1).

Qualification on stable Rust/Cargo 1.99.0, Linux x86_64:

- `cargo test -p kode-rest`: **32 passed**: 12 R01, 3 variable-resolution and 17
  request-resolution cases. All five original resolver cases are translated.
- Additional cases cover every body mode, raw language/Content-Type overrides,
  duplicate/disabled entries, inherited headers, auth types/ordering, URL encoding,
  fragments/structured URLs, GraphQL variables, missing files, canceled/oversized
  reads, multiple/binary multipart files, boundary/header consistency and collisions,
  prepared-byte immutability, preview truncation, unsafe headers, unsupported modes,
  cycle/expansion limits and secret-safe diagnostics.
- `cargo clippy -p kode-rest --all-targets -- -D warnings`, formatting and diff checks
  pass. `cargo check --workspace` passes.

Pure planning has no filesystem/network effects. Body materialization is a worker
operation and validates files before an executor can use the returned prepared
request. R04 will qualify this against real loopback servers; R05 owns streaming
transports, and R07 owns UI integration. Previews are explicitly logical rather
than exact network captures. Variable limits and caller buffering/display limits
are documented API bounds, not hard process RSS guarantees. No real endpoints,
credentials or developer request collections were used.
