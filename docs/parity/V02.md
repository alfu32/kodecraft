# V02 — Byte buffer and hex viewer

Status: done  
Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`  
Compiler: latest stable `rustc 1.99.0 (b940084d7 2026-09-28)`.

`ByteBuffer` uses its own `ByteIndex`, a bounded cursor, directional anchor,
normalized half-open selection, exact local byte clipboard, copy-on-write clone,
insertion/deletion and borrowed viewport slices. No binary operation converts
bytes through UTF-8 or uses text-coordinate validation. Empty paste preserves the
selection, matching the source. No focused Kotlin ByteBuffer/hex test suite exists;
the production buffer/view and HelpView bindings were audited directly.

`HexView` renders uppercase offsets and paired hex/printable-ASCII cells. Both
columns map to the same byte identity, selection and cursor. Arrows, Shift
selection, row Home/End, pages, wheel, drag/release, Ctrl+A and Alt+C/X/V match the
reference. Page movement starts at a row boundary and clears selection as in the
source. The view clips safely in small/empty panes, captures dragging outside its
pane, drops capture on focus loss, and clears only its owned surface.

Worker routing now opens binary/unsupported images in hex with visible decoder
feedback, and offers raw byte inspection when a text extension hides invalid
UTF-8. Reads reject special files, cancellation, changing files and files above
64 MiB; read errors never become successful empty buffers. Open binary views
retain current bytes across editor/view switches and rename. Recents record HEX
and active-origin restoration can reopen non-text viewers without editor history.

Source behavior: binary copy/cut/paste uses a private byte clipboard. The original
view has deletion/paste but no hex-digit input, physical save, undo history or
binary-buffer session format. Rust preserves this: edits remain in memory for the
workspace lifetime, physical bytes remain unchanged, and restart reads the file.
The footer and Help explicitly state that binary saving is unavailable. This is
not advertised as a complete binary editor or native text clipboard integration.

Changed paths: `kode-core/src/document/bytes.rs`, `kode-tui/src/viewers/hex.rs`,
application worker routing/state/dispatch, byte/view/application/bootstrap tests,
`scripts/test-hex-terminal.py`. Shared contract addition: binary `ByteIndex`,
`ByteViewport`, `ByteBuffer`; `PreparedViewer` routes owned worker results.

Acceptance evidence:

- Three core regressions cover every byte value, reverse selections, exact local
  clipboard/clone, invalid UTF-8, empty/partial/extreme viewport bounds, insertion,
  deletion and cursor clamps.
- Four view regressions cover golden hex/ASCII cells/colors, both mouse columns,
  absolute coordinates, reverse drag, outside release, focus loss, row/page/wheel
  controls, clipboard bindings and tiny clipped surfaces.
- Application and worker integration cover actual binary routing, temporary cut,
  reopening, UI-driven rename with spaces, persisted recents/active origin,
  restart, invalid UTF-8 fallback, cancelled/missing/oversize input.
- `cargo test --offline --workspace --quiet` — all 187 tests passed.
- Workspace check, all-target Clippy with warnings denied and format check passed.
- `python3 scripts/test-hex-terminal.py` — three actual application PTYs passed
  at 120×30, 20×6 and 1×1, including cut/paste, page/End, quit, original termios
  and screen/cursor/paste restoration. Physical bytes stayed unchanged;
  [V02-pty.json](V02-pty.json) records the results.

Decoder registration and image controls belong to V03. This baseline retained
