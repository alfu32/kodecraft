# D06 — Lazy metadata and cache invalidation

Status: done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68` in the unchanged,
clean `../kode` tree. References: `DatabaseMetadata.kt`, metadata DTOs,
`DatabaseService.kt`, `MetadataCacheTest.kt`, `JdbcDatabaseIntegrationTest.kt`.

Java `metadata/MetadataService.java` implements lazy normalized catalog, schema,
category, table/view, routine/parameter, type, column, primary-key and index
introspection; imported foreign keys add the missing normalized key category.
Names, qualified names, catalog/schema context, attributes and leaf flags are
preserved. Catalog-scoped schema/table queries retain the source's unscoped
fallback. Schema and object patterns escape literal wildcard characters, so
similarly named neighbors cannot merge into the selected object's children.
Routine children are parameters, not unrelated table indexes/keys. Every getter,
iteration and ResultSet close runs on the D04 connection owner and loader.

Capabilities are discovered lazily. Unsupported accessors add static visible
messages and update applicable capability flags, preserving other supported
sections. SQL errors propagate with SQLSTATE/vendor/chains and owner transaction
state. Standard JDBC cannot enumerate packages; the source returned an empty list,
while this implementation explicitly reports that limitation. No speculative
vendor queries or invented packages are presented as supported.

Native `metadata::Metadata` exposes inert construction/cache reads, introspect,
individual invalidation, datasource refresh, current-result validation and joined
shutdown. It uses D01 DTOs without introducing another object model. Cache keys
include datasource, helper epoch, connection ID, context/native connection
revisions and the complete request. Reconnect, context changes and helper loss
cannot reuse old entries; outstanding replies are checked again before caching.
Refresh also invalidates outstanding request generations. Already cached unrelated
nodes survive refresh; unrelated pending reads may conservatively need a retry.
Every SQL submission and final increments native connection revision, covering DDL
and procedure effects without guessing from SQL text. This may also invalidate
after read-only statements. `is_current` lets D07 reject a result that became stale
between future completion and application-thread tree mutation.

Limits are explicit: 16 native requests, 60-second waits; 256 cache entries /
16 MiB encoded cached payloads; 10,000 returned objects / 3 MiB encoded objects;
50,000 scanned rows, 8 KiB metadata strings, 4 KiB request identifiers. Excessive
responses fail with SQLSTATE 54000 rather than silently truncating the tree.
Native decoding independently validates size, duplicate IDs and attribute bounds.
UI-retained result Arcs and driver allocations are outside cache accounting.
Cancellation/drop ends native waits without caching; an uninterruptible metadata
getter can remain on the JDBC owner until return, disconnect/abort or helper
shutdown. No automatic retry/replay or connection creation occurs.

Acceptance evidence on stable Rust/Cargo 1.99.0, Java 21.0.9, Maven 3.9.16,
Linux x86_64, using only synthetic fixtures:

- `bash scripts/test-jdbc-bridge.sh`: **62 Java tests** and **37 Rust integration
  tests passed**, including all five opt-in actual-helper tests. Metadata's actual
  native→Java→H2 workflow traverses the tree, reads foreign keys, caches immutable
  results, executes DDL, changes context, reconnects and confirms invalidation.
- Seven Java metadata tests cover H2 catalogs/schemas/categories/tables/views/
  types/columns/primary/foreign keys/indexes, attributes and leaves; literal `_`
  pattern handling; representative server catalog fallbacks; unsupported sections
  preserving supported children; routine parameters; genuine SQL errors; explicit
  limits, ResultSet cleanup and cancellation; and the real serialized owner path.
- Native tests port the original individual/datasource invalidation expectations,
  preserve unrelated sources, reject late replies after refresh/context/reconnect,
  invalidate on SQL and helper crash, and cover inert/no-Java construction,
  cancellation/drop/shutdown, unsupported messages and malformed duplicate IDs.
  The final additional regression verifies a metadata SQL failure applies the
  owner's transaction state and retains SQLSTATE. Final focused run:
  `cargo test -p kode-database --test metadata --lib`: **13 passed / 1 opt-in
  ignored**; that actual-helper test passed in the full bridge run above.
- Two native unit tests cover bounded cache eviction/retained-reader lifetimes
  and the [shared metadata fixture](../../protocol/jdbc-v1/metadata-fixtures.json).
  Java reads the same fixture, preserving Unicode qualified names, foreign-key
  attributes, context revision and unsupported messages through actual framing.
- `cargo test --workspace`: **442 passed / 5 opt-in ignored** before the final
  additional error-state regression, which passed in the focused run above.
  `cargo check --workspace`, database/TUI clippy with `--all-targets -- -D warnings`,
  formatting and diff checks pass. Catalog verification still matches all 59
  frozen definitions and exact URL templates; protocol JSON parses successfully.

No interactive metadata UI is claimed: D07 composes the explorer/dialogs and must
check workspace/request tags plus `Metadata::is_current` before publishing a tree
reply. Shutdown Metadata before Connections. External server fixtures are
deterministic metadata proxies, not claims of live PostgreSQL/MySQL/Oracle/SQL
Server qualification; those remain D09. External schema changes require explicit
refresh. Non-Linux and complete migration qualification remain Z04.
