# W03 — Legacy session import and Rust persistence

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable, Linux x86_64.

`kode-workspace/src/session/` implements the [version-1 schema](../formats/session-v1.md),
Kotlin v6 import, current-disk restore with dirty recovery, atomic guarded persistence,
three-second debounce, bounded worker writes and orderly shutdown flush. It uses
the actual ProjectSession/BufferState DTOs and Main's recents/mtime behavior. The
legacy file remains untouched. Fresh source-root defaults apply only when neither
session exists; saved empty roots preserve the user's selection.

Every UTF-16 cursor/anchor in current/undo/redo state converts using its own text,
including emoji, reverse selection, negative/oversized/surrogate-interior positions.
History, dirty text, virtual SQL origins, raw CRLF/BOM format, grammar, visual scroll,
viewer kinds and timestamps survive Rust round trips. The core history contract
adds a backward-compatible `saved_baseline_known` flag so a dirty legacy buffer
without saved text cannot become falsely clean; `DiskIdentity` now supports serde.
REST/database/unknown feature fields and arbitrary precision numbers stay owned
JSON until their feature service validates them. Legacy property-name collisions
are preserved in namespaces instead of emitting duplicate JSON keys.

Writes serialize on workers, preserve a previous good Rust file, use E04 guarded
atomic save and never replace malformed/future-version or externally changed state.
Completion of an older write cannot mark newer session edits clean. Failed writes
retain pending state. Stale dirty buffers are recovered to restricted, unique files
before publishing fresh disk content; recovery failure prevents publication.
Missing/read-error feedback retains persisted content. Corrupt Rust state can load
its previous snapshot with a warning while keeping the corrupt file and blocking
automatic writes. Future versions are rejected without rollback.
