# U09 — Repair language server installations

Status: suspend (user-requested). The task remains open for native ARM64, macOS and other
remaining platform qualification.

The installer supports isolated, checksum-pinned package closures, explicit
Node/Java prerequisite checks, a direct JDT launcher with project-specific state,
and readable, scrollable operation errors in Settings. Editing a generated
manifest command retains the local-executable override. JDT configuration is
versioned by archive identity so upgrades retain project data while replacing
OSGi bundle configuration.

Six actual upstream Linux x86_64 installs complete LSP initialize, didOpen,
shutdown and child reaping using production lifecycle defaults: TypeScript,
HTML, CSS, JSON, JDT LS and clangd. On 2026-10-17 the combined default LSP/TUI
suite passed 349 tests with seven opt-in external qualifications ignored; the
LSP package contributed 46 passing tests and three explicit upstream tests
ignored. The Linux ARM64 catalog runtime also passed separately under QEMU.
Four real CLI terminal cases cover full error copy/save and runtime rejection
before download at wide and narrow sizes.

On the authorized Windows x86_64 host, 33 applicable LSP regression tests pass,
including the Debian adapter, declared copies and native process-exit probes.
Fresh TypeScript/HTML/CSS/JSON/JDT/clangd installs pass the production lifecycle
in 62.07 seconds with unchanged deadlines. An initial HTML timeout passed both installed and
fresh replays after the host restart with the original deadline unchanged; its
cause is not established. JDT then failed on its Unicode configuration/cache
path. The encoded file URL repair now passes an actual native Windows installed
replay: initialize in 3.7 seconds, didOpen, shutdown and reaping. A first repaired
startup timed out at 10 seconds; its cause remains unestablished, and the passing
replay retains the original deadline. The separate fresh run initializes JDT in
3.4 seconds and clangd in 98 ms. Native Windows Clippy also passes. These LSP tests use an
isolated GNU toolchain and do not qualify Z03's MSVC application artifacts.

Official release metadata confirms the standalone clangd 23.1.0 release has no
Windows ARM64 asset. The official LLVM ARM64 Windows archives currently exceed
the installer's 256 MiB download bound, and the MSI is not a supported input
format. The remaining options and exact sizes are recorded in the
[Windows ARM64 asset inventory](U09-assets.json#L521); no Windows ARM64 runtime
qualification is claimed.

The [Debian archive report](U09-deb.json) verifies actual official ARM64 clangd
download/extraction through the production installer, including its ELF header,
selected tree and license. Control scripts never run, Zstandard memory is bounded,
and malformed packages leave old installs intact. Library/resource archives and
ELF dependencies are verified. Explicit regular-file copies supply pinned SONAME
aliases without following archive links. A bundled GNU loader checks the private
library closure before publication and launch, using managed, cancellable probes.
The pinned Ubuntu Jammy closure is now enabled as a Linux ARM64 clangd catalog
version. A fresh run selects it from the production catalog and passes installation,
private-library checks, initialize, didOpen, diagnostic-free bundled-header
resolution, shutdown and child reaping under QEMU. Native ARM64 hardware
qualification remains open; emulation does not qualify Z03 artifacts.

The [isolated ARM64 runtime report](U09-arm64.json) records a fresh 19-archive
closure, including its own glibc loader and libraries. Under private QEMU, all
shared libraries resolve inside the install; production lifecycle defaults pass
initialize, didOpen, parsing without diagnostics, a definition into bundled Clang
headers, shutdown and reaping. Spaces, Unicode and a colon in the install path
are covered. The launch command expands the resource directory while keeping the
manifest relocatable. This is explicitly emulated execution on Linux x86_64.

This is a progress checkpoint, not U09 acceptance or assembled release evidence.

the file to render and is not the focus-fix evidence.
