# U09 — Repair language server installations

Status: in-progress. The task remains open for Windows JDT/clangd, remaining
native platforms and ARM64 installation support.

The installer supports isolated, checksum-pinned package closures, explicit
Node/Java prerequisite checks, a direct JDT launcher with project-specific state,
and readable, scrollable operation errors in Settings. Editing a generated
manifest command retains the local-executable override. JDT configuration is
versioned by archive identity so upgrades retain project data while replacing
OSGi bundle configuration.

Six actual upstream Linux x86_64 installs complete LSP initialize, didOpen,
shutdown and child reaping using production lifecycle defaults: TypeScript,
HTML, CSS, JSON, JDT LS and clangd. The affected suite passes 342 tests on stable
Rust 1.99.1. Four real CLI terminal cases cover full error copy/save and runtime
rejection before download at wide and narrow sizes.

On the authorized Windows x86_64 host, 26 applicable LSP regression tests pass,
including native process-exit probes. Fresh TypeScript/HTML/CSS/JSON installs
pass the production lifecycle. An initial HTML timeout passed both installed and
fresh replays after the host restart with the original deadline unchanged; its
cause is not established. JDT then failed on its Unicode configuration/cache
path. The encoded file URL repair passes focused tests and an actual Linux
JDT replay; Windows replay remains pending after SSH became unavailable again.
Windows clangd and Windows Clippy also remain pending, as does replaying Windows
regressions with the new Debian adapter. These LSP tests use an
isolated GNU toolchain and do not qualify Z03's MSVC application artifacts.

See the [implementation and remaining qualification](../migration/U09-INTEGRATION.md),
[Linux upstream runtime results](U09-upstream.json),
[partial Windows results](U09-windows.json),
[verified asset inventory](U09-assets.json), and

The [Debian archive report](U09-deb.json) verifies actual official ARM64 clangd
download/extraction through the production installer, including its ELF header,
selected tree and license. Control scripts never run, Zstandard memory is bounded,
and malformed packages leave old installs intact. Library/resource archives and
ELF dependencies are verified; their isolated closure, launcher and ARM64 runtime
remain open. The candidate is a fixture, not an enabled catalog entry.

This is a progress checkpoint, not U09 acceptance or assembled release evidence.
Z03's [complete artifact matrix](../migration/Z03-ARTIFACT-MATRIX.md) remains queued
after U01–U12. E13 separately tracks the delayed initial-file-load focus race
observed during terminal replay.
