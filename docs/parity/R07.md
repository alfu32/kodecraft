# R07 — Request/response editors and complete REST UX

Status: in-progress

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`, clean.
Read `RestCodeFormatting.kt`, `HttpHeaderCatalog.kt`, their original tests and
the request view's rendering, dispatch, header-editor and mutation paths. R06's
application owners and sidebar execution callback are available. This report is
implementation and acceptance evidence.

Implemented so far:

- `kode-rest/src/format.rs`: content-type/language mapping and optional worker
  display formatting for JSON/GraphQL JSON, XML, HTML, JavaScript and conservative
  YAML whitespace cleanup. Disabled, invalid, cancelled and over-budget input
  stays borrowed/unchanged. Raw request/response bytes are never mutated by this
  API. JSON validation uses serde_json and token formatting preserves duplicate
  keys, order, numeric precision/spelling and escapes. XML uses the already locked
  roxmltree 0.21.1 with DTD disabled, no external resolver and a node limit; original
  attributes/entities/CDATA and mixed-content/xml:space regions are preserved.
  HTML/JS use the existing pinned tree-sitter languages, then reparse and compare
  syntax structure before returning a formatted result. Strings, comments, regex,
  templates, HTML raw/preformatted text and JS automatic-semicolon boundaries
  remain intact. Formatting traversal is bounded; this is not a hard RSS claim.
- `kode-rest/src/headers.rs`: the source's complete HTTP field-name catalog,
  case-insensitive suggestions excluding active names on other lines, and source
  earlier-duplicate warning indices. Value focus does not produce header-name
  suggestions; disabled rows retain their distinct behavior.
- `kode-tui/src/panels/rest/editor/headers.rs`: production shared-editor provider
  and warning configuration. It compensates for the editor's general word-prefix
  treatment of hyphens, so `Content-T` completes through the real popup without
  duplicating `Content-`. Automatic popup display remains off, matching source.
  This adapter still needs attachment to the complete request view.
- Request planning now limits aggregate expanded values and repeated path-variable
  output to 64 MiB. Per-value bounds alone allowed a small document to repeatedly
  expand one large variable into unbounded accumulated data before body/network
  validation. Two real-resolver cases now fail with explicit planning-limit errors.
  Percent encoding builds one buffer instead of allocating a string per byte.
- `model/editing.rs` now supplies the scoped mutations for collection/folder and
  request fields, auth, variables, query/path rows, all body modes, settings and
  explicit import acknowledgement. Dialog entry values are shared with the TUI.
  Header edits preserve metadata through key changes, ordering and duplicate
  occurrences; opaque array entries remain present and invalid text is atomic.
  Body-mode changes retain inactive data, and multipart file edits update the
  actual `src` used by the resolver, including path arrays. Structured descriptions
  keep their extra fields, while unedited structured values retain their JSON type.
- Raw URL host/path edits retain existing query metadata. Explicit raw-query edits
  replace the stale structured representation so it cannot override the URL.
  Structured query edits decode once, retain ordering/duplicates/fragments and
  keep disabled rows out of the regenerated raw URL. Explicit null query values
  preserve key-only flags, as in the [Postman SDK source](https://www.postmanlabs.com/postman-collection/collection_query-param.js.html).
  This fixes the source UI's re-encoding of already encoded raw-query values.
- `editor/form/` implements the request-control component: method/URL/Send targets,
  keyboard/mouse tabs, auth/variable/query/path/body/settings rows, bounded fields,
  masked row dialogs, import-review action, cookie/notices callbacks and clipboard
  proofs. Model identity changes reject stale dialog results; tree removal closes
  the target and moves rebase it. Display rows are cached against weak collection
  identity, tab and reveal state instead of recreating label strings every frame.
  AppState now attaches these controls around the shared request editors.
- `editor/buffers.rs` prepares real shared-editor documents off thread for headers,
  raw bodies, GraphQL query/variables and read-only raw request previews. Installation
  binds the existing document registry, header provider, warnings and SendRequest
  ownership. Captured ropes override pending semantic publication; invalid header
  captures fail before materialization, and unrelated invalid buffers cannot block
  another request's preview. Raw preview uses the current environment rope and
  displays the WS receive-only/transport-normalization context. Raw body bytes and
  unfinished drafts remain unchanged. Application-owned jobs now route their results.

Application composition:

- Request opening now prepares a real form on a worker and attaches it through
  the existing modal/focus gate. Stable runtime item keys retain forms, document
  IDs, caret, scroll and undo history across request switches and tree moves.
  Removed/replaced items dispose their buffer owners. File, SQL, environment,
  import-notice and Git diff opens supersede request forms.
- Header/body/GraphQL edits publish exact-revision worker results into their
  original item. Header completion and duplicate warnings use the common editor.
  Cached body documents keep history while refreshing syntax from current valid
  effective Content-Type headers, including unpublished header ropes. Large
  inherited sections scroll above a pinned local editor; cached row offsets bound
  painting to visible rows.
- Send/Ctrl+Enter captures current ropes synchronously before queued semantic
  publication. Strict worker merging rejects invalid headers before network I/O;
  unrelated invalid drafts do not block another request. Run preparation freezes
  semantics and validates structural generation; keys assigned by new views are
  reconciled before execution. Folder/collection Ctrl+Enter never silently starts
  a batch; the sidebar provides that explicit action. The native find bar retains
  Ctrl+Enter precedence, including embedded and readonly preview hosts.
- Owned `x-kode-rs-request-buffers` stores unfinished request text separately from
  Postman export. Worker persistence merges valid drafts and retains invalid text
  with the last valid typed model. Unknown draft kinds remain preserved. Tree
  changes rebase unopened drafts; current ropes override saved versions. Active
  REST request restore uses a persisted model path, and explicit CLI files keep
  precedence over saved views and recent-file fallback.
- Responses use a separate shared readonly editor with Body, Headers, Cookies,
  Raw and Transaction tabs, a draggable divider, preserved scroll/caret, display
  formatting, cookie inspection/clear and status/time/byte/error/truncation/close
  feedback. Pretty response formatting never changes captured bytes; binary text
  conversion is explicitly labelled. Request body formatting is an explicit,
  revision-guarded, undoable command.
- SSE/WS progress publishes bounded snapshots (10 MiB / 4096 chunks) while keeping
  the authoritative final response. One worker display job runs at a time; newer
  snapshots follow intermediate publication. Async tab changes, modal attachment
  and request switches cannot install an old response under another item or steal
  request focus. Ordinary HTTP retains its completion-publication contract.
  Transaction displays configured/normalized logical requests, normalization
  notices and response text; it makes no TLS packet/redirect-hop capture claim.
- Superseding/discarding cancellable jobs now releases their context maps even
  when the scheduler omits cancelled delivery. The resource regression proves
  that a context's last strong collection reference is dropped immediately.

Acceptance evidence:

- `rest_form`: eight cases cover method/URL/Send, every tab and remaining control
  family through rendered mouse targets, field/row mutation, dialog/clipboard
  identity, import review, secrets, body modes, 2000 inherited headers, and tiny
  views. Generic dialog tests retain their separate full field/button coverage.
- `rest_app`: nineteen actual AppRuntime cases include original environment and
  focused-header/transaction regressions, Send from unpublished header/body ropes,
  native search precedence, request switching/history, formatting undo/stale
  revision, invalid raw draft restart and explicit startup-file precedence.
  Loopback HTTP/SSE/WS exercise incremental publication, owner changes, binary
  bytes and normal close, default WS receive-only behavior and raw-preview
  Ctrl+Enter. All five response tabs, readonly copy/mutation guards, Pretty,
  cookie clear and response dragging run through application callbacks.
- `rest_buffers`, `completion` and `editor_host` cover worker installation, MIME,
  header suggestions/warnings, resolver preview/current ropes, missing files,
  cancellation, shared clipboard/search, and all readonly mutation paths.
- `scripts/test-rest-editor-terminal.py`: four real CLI PTYs at 100×34 and 60×34
  type headers/body, send to loopback, switch response tabs, verify header caret
  arrows while Transaction is visible, reject response paste, open raw preview,
  quit and restore the owned body. HTTP receives only the intended two requests;
  response text/runtime cookies never enter persisted state. Terminal modes and
  termios restore. [Recorded evidence](R07-pty.json).
- App/runtime regressions: all sixteen application runtime cases and seven
  non-fixture database cases pass. Actual Java/H2 cross-feature qualification is
  recorded separately under D09; no ignored fixture is counted as passed here.
