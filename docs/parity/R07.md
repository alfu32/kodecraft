# R07 — Request/response editors and complete REST UX

Status: in-progress

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`, clean.
Read `RestCodeFormatting.kt`, `HttpHeaderCatalog.kt`, their original tests and
the request view's rendering, dispatch, header-editor and mutation paths. R06's
application owners and sidebar execution callback are available. This report is
partial evidence; the complete request/response UI is not implemented yet.

Implemented so far:

- `kode-rest/src/format.rs`: content-type/language mapping and optional worker
  display formatting for JSON/GraphQL JSON, XML, HTML, JavaScript and conservative
  YAML whitespace cleanup. Disabled, invalid, cancelled and over-budget input
  stays borrowed/unchanged. Raw request/response bytes are never mutated by this
  API. JSON validation uses serde_json and token formatting preserves duplicate
  keys, order, numeric precision/spelling and escapes. XML uses the already locked
  roxmltree 0.21.1 with DTD disabled, no external resolver and a node limit; original
  attributes/entities/CDATA and mixed-content/xml:space regions are preserved.
  HTML/JS use the existing pinned tree-sitter languages, then reparse and compare
  syntax structure before returning a formatted result. Strings, comments, regex,
  templates, HTML raw/preformatted text and JS automatic-semicolon boundaries
  remain intact. Formatting traversal is bounded; this is not a hard RSS claim.
- `kode-rest/src/headers.rs`: the source's complete HTTP field-name catalog,
  case-insensitive suggestions excluding active names on other lines, and source
  earlier-duplicate warning indices. Value focus does not produce header-name
  suggestions; disabled rows retain their distinct behavior.
- `kode-tui/src/panels/rest/editor/headers.rs`: production shared-editor provider
  and warning configuration. It compensates for the editor's general word-prefix
  treatment of hyphens, so `Content-T` completes through the real popup without
  duplicating `Content-`. Automatic popup display remains off, matching source.
  This adapter still needs attachment to the complete request view.
- Request planning now limits aggregate expanded values and repeated path-variable
  output to 64 MiB. Per-value bounds alone allowed a small document to repeatedly
  expand one large variable into unbounded accumulated data before body/network
  validation. Two real-resolver cases now fail with explicit planning-limit errors.
  Percent encoding builds one buffer instead of allocating a string per byte.
