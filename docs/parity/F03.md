## Runtime contract and acceptance evidence

- Bounded scheduling: 64 completion slots, 32 async operations, 4 blocking
  workers; admission rejects excess work. Repaint coalesces independently of
  keyboard input. Latest progress is bounded to 64 owners/512-character messages.
- Owner/workspace cancellation has an independent control path. Cancellable
  previews can stop waiting for queue capacity. Critical save/failure completions
  remain deliverable under saturation. Shutdown cancels owners, concurrently
  drains those completions, then joins every async and blocking worker.
- Blocking closures are joined and must cooperate at safe cancellation points;
  they are never detached by dropping their awaiting future. Worker panics become
  explicit errors. Clock, process factory and worker scheduler are injectable.
- Main-thread `ResultGate` rejects delayed A after B, workspace switches, document
  revisions/closure, stale snapshot requests and dismissed popup responses.
- Managed child pipes use independent stderr draining with a 64 KiB tail. Capture
  drains beyond its 4 MiB stdout preview limit and records truncation. Child stdin
  closes for EOF, and explicit cancellation/termination waits for exit/reaping.
  Unix children run in an owned process group; termination also kills descendants,
  preventing inherited pipes from hanging after parent exit. Drop requests group
  cleanup and Tokio's kill-on-drop backs up explicit lifecycle operations.
- Resource precedence: explicit → Rust home → executable → compiled defaults;
  legacy home is a fallback only without a Rust-specific override. Configuration
  goes to `kode-rs`; runtime construction launches no Java/LSP/ttyd process.
  Embedded licensed theme, keyword/color/intelligence/LSP/JDBC catalogs and all
  **281 MIME entries**, including positional image/binary entries, work away from
  the repository. Copied MIT license remains in resources.
- JSON-lines logging is synchronized and bounded with one previous file. It
  writes to files and never to a widget/stdout canvas.

## Validation

Passed: focused platform/TUI tests (12 tests: seven runtime, four host, one result
gate); workspace `cargo check --offline`; `cargo fmt --all --check`; focused
`cargo clippy --all-targets --offline -- -D warnings`.
Key tests cover delayed/fast ordering, idle repaint, saturated critical results,
cooperative blocking cleanup, panic/error delivery, progress coalescing, scheduler
injection, missing processes, resource precedence, log rotation, EOF/nonzero
exit/stderr/cancellation, descendant pipes and all stale result dimensions.

Resolved adoption: Tokio 1.53.3, Tokio-util 0.7.20, futures-util 0.3.34, tempfile
3.27.0, Unix nix 0.30.1. Selected manifests/source were inspected; lockfile records
features and dependency versions. nix supplies safe process-group signal APIs;
workspace Rust code continues to forbid unsafe code.

Manual terminal checks belong to F04. Process tests ran on Linux; Windows/macOS
runtime adapters are implemented through Tokio but full platform qualification
remains Z04. Arbitrary blocking native calls cannot be forcibly stopped safely;
owners must supply cancellation checkpoints and shutdown waits for them.
Application shutdown order: stop admission/input effects, cancel owner/workspace
jobs, close/terminate protocol children, drain critical writes/results, persist
session and join workers, then restore terminal modes (F04/W03/W05 integrate this).
