## Behavior and acceptance

File loading, strict UTF-8 decoding and rope construction run in bounded blocking
workers. Main-thread publication checks request/workspace/document/target identity.
Late results are discarded; missing/denied/malformed text produces a visible typed
error rather than an empty document that can overwrite the original. Worker-prepared
documents carry BOM/newline metadata and disk identity.

Unchanged UTF-8/BOM/LF/CRLF/mixed/no-final-newline files round-trip exactly. Saves
write a sibling temporary, preserve Unix owner/group and permissions, flush it,
recheck canonical path/timestamp/length/SHA-256 identity, then atomically replace
and flush the directory. Saving through a symlink preserves the symlink and target;
changed targets, read-only files and unexpected existing new-save destinations
reject overwrite. Malformed/non-UTF-8 text is an explicit decoding error; optional
additional encodings are not inferred silently.

One active save per document serializes physical writes. Newer requested snapshots
wait and use the preceding save's new disk identity. A successful older save updates
only its saved baseline; newer edits stay dirty and their history remains intact.
Failures remain typed/visible/dirty. Virtual labels never become filesystem paths;
the native I/O adapter rejects them, while E12 supplies explicit host save/export.

The shared clipboard provides lazy Arboard native access and an internal fallback.
Ctrl/Alt C/X/V map consistently; bracketed paste remains one core edit. Local copy
epochs are remembered before native publication. Pending/late copy/read jobs cannot
replace a newer copy, and all native operations are serialized away from drawing.
Headless construction launches no desktop connection, and fallback requires no
terminal query. Native clipboard objects remain owned until service disposal.
Arboard 3.6.1 is pinned without image-data; SHA-256 uses sha2 0.10.9. Selected sources
and [Arboard's API](https://docs.rs/arboard/3.6.1/arboard/struct.Clipboard.html) and
[atomic tempfile APIs](https://docs.rs/tempfile/3.27.0/tempfile/struct.NamedTempFile.html)
were inspected.
