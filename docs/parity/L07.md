# L07 — Expression types and receiver member lookup

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(intelligence): infer receiver expressions and assignment unions`.

The resolver evaluates actual expression structure, propagates reference/call/cast/
literal/assignment types until stable, retains nullable/generic/function shape,
and merges conflicting assignments into deterministic unions. Lookup unwraps
nullable/generic receivers and follows aliases/inheritance with visibility checks.
Union members must exist on every alternative; distinct declarations keep distinct
identities rather than publishing an arbitrary target. Callable values retain their
own identity, while invoking a noncallable value stays untyped. Unknown AST calls
never fall through to a constructor-name heuristic.

L01's file delta gains a defaulted native `syntaxExpressions` extension: raw byte
ranges, scope/occurrence identities, operands, explicit type arguments, casts and
assignment targets. It carries unresolved syntax, not live Tree-sitter pointers or
invented compiler facts. Kotlin/C frontends emit it, validation checks its ranges
and references, and SQLite retains it separately from enriched expression types.
The native cache format signature advances to `utf8-semantic-v2`; identified older
caches rebuild. AST structure prevents call arguments from replacing the outer
return type and permits consistent reconstruction after restart/invalidation.

Prepared expression queries select the full matching receiver value ahead of
contained argument literals. Generic constructor arguments survive inference;
untyped exported expression bindings contribute to semantic surface hashing while
literal value changes with the same inferred type remain implementation-only.
Indexed scope/member names, inheritance edges and C type contexts avoid repeated
whole-scope scans. Binding evaluation observes prior updates immediately, so a
100-variable reference chain resolves without one global pass per variable.

Kotlin's upstream recovery around a dangling `.`/`?.` can discard the enclosing
class or split a receiver chain. L02 parser preparation masks only incomplete
access operators with same-length ASCII spaces outside strings/comments/backticks.
The published snapshot/source and saved bytes remain original. Incremental edits
compare the actual prepared parser inputs, preserving fresh/reused equivalence
when a member is typed or removed. Recovery is explicitly reported as partial
syntax status. Native code still has no compiler or preprocessor guarantees.

Thirteen `tests/expression_types.rs` tests reproduce every named source
KotlinExpressionSemanticsTest scenario and extend them with argument-bearing calls,
navigation initializers, explicit generic constructors, callable parameters,
noncallable shadows, ambiguous union identities, cyclic unknowns, a 100-reference
chain, union limits, C qualified pointer casts and real SQLite restart queries.
The receiver results include chained properties/methods/functions; casts and nested
parentheses; propagated references/assignments; common union members; primitive
literals; unknown receivers; nullable generic members; and `this`/`super` visibility.
The parser recovery test checks original CRLF bytes, scope retention, valid multiline
access, strings/comments/ranges/import wildcards and incremental restoration of a
masked operator versus fresh parsing.

Validation passed on stable Rust 1.99.0:

- `cargo fmt --all --check`.
- `cargo check --offline --workspace --all-targets`.
- `cargo clippy --offline --workspace --all-targets -- -D warnings`.
- The final propagation optimization additionally passes the complete intelligence
  and syntax suites plus their Clippy checks; `git diff --check` passes.

Limits include 64 inference passes, 64 union alternatives and depth-limited
expression/type traversal under the resolver's cancellation/work budget. Exhausted
union inference stays unknown with an explicit note; partial facts remain useful.
These are best-effort facts, with no overload selection, full generic substitution,
control-flow typing or compiler validation. No terminal check applies to this worker
API; L09/E11 attach native providers/overlays and expose status notes. Next: L08.
