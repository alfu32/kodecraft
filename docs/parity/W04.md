# W04 — Project search modal and embedded editor

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable, Linux x86_64.

`kode-workspace/src/search.rs` implements cancellable whole-project text traversal
independently of source roots, exclusions and Git ignore rules. Hidden, ignored,
excluded and build/target text files are included; Git/session metadata, binary
classifications, directory links/cycles and outside-project aliases are skipped.
Canonical files are deduplicated. Relative-path filename filters use Java-compatible
regex, compiled once with the query through the core `SearchRegex` boundary. As in
ProjectSearcher.kt, query matching is per line, including zero-width results and
no synthetic trailing empty line. Raw UTF-8 ranges map BOM/CRLF and supplementary
scalars correctly. Live open snapshots supply unsaved text without replacing their
history or reading it back from disk.

Workers prepare hit text, byte/UTF-16 coordinates, document revisions or actual disk
identity and optional source syntax spans. File reads cap at 16 MiB, result count
at 100000, and warnings at 128 plus an omitted count. Size/UTF-8/read/traversal errors
are recorded, regex/match-limit failures reject the result, and cancellation never
publishes partial success. `SEARCH_SCOPE` documents the exact policy. Native file
opening now rejects directories/pipes and uses Unix nonblocking open plus descriptor
validation, preventing a stat/open race from trapping a worker on a FIFO; MIME
sampling reuses that platform boundary.

`kode-tui/src/panels/project_search/` renders a centered modal with search/replacement/
filename-filter fields, hit markers, prepared colored Unicode-safe lines, file labels,
keyboard/wheel selection, draggable splitter and shared `EditorView`. Literal selection
and extension-based filter prefill preserve source behavior. Modal focus is separate
from preview focus; clipboard tickets validate field/value/caret/focus, late search/load
results validate their request, and outside dismissal restores the previous focus.
F1 explains scope. Empty and tiny layouts remain clipped inside the modal.

The shell responds to `OpenHit` with an existing registry document or actual worker
load before attaching a view; failed loads remain errors instead of empty editable
buffers. Attach validates origin/range/revision and centers the selected match. Switching
hits detaches views while keeping registry-owned text/history/saves. Preview changes
invalidate stale matches and rescan after a 150 ms debounce using current snapshots.
Ctrl+S saves the preview even while a search field owns keyboard focus. Child popup/
drag/search dispatch remains ahead of modal dismissal. Editor clipboard and replacement
use the shared E07/E12 paths. Project-wide replace commands are intentionally not
implemented: the source handler ignores them; no bulk replacement is claimed.
