# P02 — LSP client transport and lifecycle

Task: P02. Status: done.
Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`; reference tree clean.

Implemented `kode-lsp/src/{transport,documents,client,service}.rs`, the F03 managed
child wait/cancel adapter, actual settings process-service composition, synthetic
stdio peer and terminal qualification. Read LspClient.kt/LspService.kt and selected
`lsp-types` 0.97.0 source. Public boundaries and limits are in CONTRACTS.md.

Frames count UTF-8 bytes and accept fragmented/concatenated messages with bounded
headers/bodies. Requests have unique IDs, bounded pending state, out-of-order
response routing, typed error results, deadlines and best-effort cancellation.
Reader/writer/document/supervisor actors use the existing Tokio runtime, bounded
queues and tracked cleanup. No UI input/render path waits for a server reply.
Stderr drains throughout startup/runtime/shutdown; its bounded tail survives errors.
Server configuration/workspace requests receive real replies. Unsupported client
methods report -32601; server edits/navigation explicitly decline.

Initialize publishes workspace/root/client capabilities and waits for initialized
to reach the pipe before claiming running. UTF-16 defaults and negotiated UTF-8/
UTF-32 map Unicode correctly. Protocol line mapping handles CR/LF/CRLF separately
from editor line policy without changing saved bytes. Incremental edits expand
across CRLF pairs rather than addressing their interior. Client document versions
remain separate from editor revisions; stale revisions fail, identity changes reset
the replica, and ordered open/change/save/close writes survive caller cancellation.
Definitions, references and completions use capability-checked lsp-types results.

The ordered workspace registry serializes lifecycle actions and never registers a
failed start as running. Settings starts/restarts actual discovered command arrays;
state/error changes request repaint without catalog I/O on the UI thread. Workspace
switch and application exit drain accepted jobs, close documents, request shutdown,
send exit, force unresponsive children when necessary, reap them and join actors.
Dropped startup/client/service ownership also cancels supervised children.

Protocol references: [LSP 3.17 specification](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)
and the [official text-document implementation](https://github.com/microsoft/vscode-languageserver-node/blob/main/textDocument/src/main.ts)
were consulted for negotiated positions and protocol newline handling. Implemented
algorithms are independently written and exercised against exact document bytes.

Limits: synthetic server qualification does not claim vendor-server compatibility
or native Windows/macOS process/terminal execution. Dynamic capability registration,
server-initiated edits and additional enrichment are not advertised as implemented.
Events are bounded transport data; diagnostics are not yet editor decorations.
Editor document attachment, request/result revision gates and non-empty-primary/
native fallback are P03. Full migration remains in progress. Next ready task: P03.
