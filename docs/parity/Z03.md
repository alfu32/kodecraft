# Z03 — Reproducible build and distribution

Status: in-progress — the requested release matrix is implemented and 0.2.8 was
successfully built and published by GitHub Actions. Separate installed-runtime
qualification remains open.

The [expanded distribution requirement](../migration/Z03-ARTIFACT-MATRIX.md)
includes portable Linux/macOS/Windows for x86_64/arm64, AppImages, Snap, MSI/MSIX
and DMG. The complete 0.2.8 artifact matrix now builds, passes the workflow's
integrity/asset gate, and is published at
[GitHub release 0.2.8](https://github.com/alfu32/kodecraft/releases/tag/0.2.8).
That release contains 67 assets, including the JDBC adapter JAR, checksums and
manifests. This proves the remote build and release pipeline; it does not replace
the separate installed-runtime qualification listed below.

The Linux x86_64 GNU archive now includes the executable/resources, separate JDBC
helper, full dependency legal texts, launcher sources and a relocated standalone
ttyd/library bundle. It contains **no JVM**. Minimum tested glibc is **2.39**.
[Archive evidence](Z03-archive.json) records **984 files**, **32,813,172 compressed
bytes** and matching independent assemblies of the same inputs:

`e16bc9d3668e9de49285b5da05f68a47d1eebd039b7fc173bf38c880b1653f59`

Legal collection covers **405 Linux Rust build/runtime dependencies**, **30 pinned
Java runtime libraries**, native components and **18 ttyd browser dependencies**.
Original copyright/developer/POM declarations and upstream source/hash provenance
are retained. The helper's full runtime closure and hashes are locked; its two
builds match. [All 64 helper tests and rebuild evidence](Z03-helper-build.json)
are qualified locally. Native libraries use relative RPATH; libuv is built into
checksummed libwebsockets/ttyd to avoid a nonrelocatable event-plugin search path.

- [Four archive/clean-OS cases](Z03-archive.json): exact manifests/modes/legal
  files, developer path absence, shell and Linux PowerShell launchers, no-Java
  PTY core, real packaged-helper H2 SQL, and browser save/disconnect in an
  unprivileged, read-only pinned Ubuntu container with no Java or CA store.
- [Five packaged browser cases over SSH](Z03-browser.json): all eight panel
  shortcuts, editing, browser clipboard, reconnect, streaming REST cancellation,
  actual H2 SQL and dirty persistence/helper reaping. Adjacent executables/helper
  are used, with no developer library path. Evidence matches the archive manifest.
- [Four AppImage PTY cases](Z03-appimage-pty.json): actual FUSE and
  extract-and-run launches, no-Java editing/save and external-Java H2 SQL, paths
  with spaces and executable-relative helper discovery. [Five actual AppImage
  browser/SSH cases](Z03-appimage-browser.json) also pass, including clipboard,
  streaming REST, SQL, dirty restart and child cleanup.
- [Installer rebuilds](Z03-installers.json): AppImage and strict core24 Snap
  assemblies repeat byte-for-byte. Snapcraft and service-free `snap pack` produce
  identical Snap bytes. The AppImage runtime/tool inputs and additional native
  runtime licenses are pinned and shipped.
- [Three strict Snap VM cases](Z03-snap-vm.json): actual installation on core24,
  no-Java edit/save/Get Java offer, external-Java real H2 SQL, and packaged browser
  editing/save over SSH. The helper and editor children are reaped; host Snap
  installations are untouched. Qualified guest: Ubuntu 24.04, snapd 2.77.1,
  kernel 6.8.0-142-generic.
- [Independent Rust/native rebuild](Z03-rebuild.json): fresh Cargo/native build
  directories reproduce the archive hash above on the same host/toolchain. This
  does not claim equality across compilers, operating systems or package updates.
  [Build provenance](Z03-build-source.json) records compilers, native package
  versions, static libuv and source hashes. Its `sourceDirty: true` accurately
  records this uncommitted implementation batch; it is ineligible for release.
- [No-Java Rust build](Z03-no-java-build.json): all workspace targets compile in
  a clean pinned container without Java, javac or Maven, with source/registry
  mounted read-only and no user Cargo credentials.
- [Thirteen release preflight cases](Z03-release-preflight.json): exact assets,
  tag/source matching, checksums, missing runtime, duplicate filenames and stale
  output rejection; mocked GitHub calls reject existing releases, wrong tags and
  authorization errors. Positive cases use explicitly synthetic clean-source
  metadata in temporary copies. The real release was subsequently built and
  published by [workflow run 39053643210](https://github.com/alfu32/kodecraft/actions/runs/39053643210).
- [Three integrity rejection cases](Z03-integrity.json): corrupt legal text,
  corrupt native library and stale helper each fail for the expected reason,
  without publishing an archive.

The clean-image fixture exposed eager LSP TLS client construction blocking editor
startup without CA certificates. Initialization is now deferred to explicit
installation on the existing blocking worker; failures can be retried after system
TLS setup is repaired. TLS validation remains enabled. Seven LSP installer tests,
19 application-runtime tests, affected all-target clippy, format, credits and task
ledger checks pass. Docker bridge routing was unavailable locally; the clean-OS
browser case uses loopback host networking and changes no host network settings.

The manual distribution workflow builds/tests the native application/helper,
assembles all six target families and optional runtimes, verifies the exact
artifact set, checksums and manifests, and publishes only after the gate passes.
The 0.2.8 run completed successfully and published all assets atomically. Its
version tag is the bare `0.2.8`, without a `v` prefix.

Actual remote builds now qualify production of each release artifact on all six
OS/CPU targets; Windows/macOS installed launcher behavior, installer install/
upgrade/uninstall behavior, and cross-platform runtime acceptance remain open.
The workflows pass local actionlint 1.7.7 validation; shellcheck was unavailable
and disabled for this check. Python compilation, credits and task consistency
checks pass. Exact commands and qualification boundaries are in the
[handoff](../migration/Z03-INTEGRATION.md) and
[distribution guide](../../packaging/README.md).
