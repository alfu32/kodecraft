# L04 — C semantic extraction

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(intelligence): extract C tags typedefs and member occurrences`.

`kode-intelligence/src/frontend/c/` consumes the selected L02 C tree and emits
source-validated L01 file facts. Tags, typedefs and anonymous struct/union/enum
definitions retain separate stable identities, including same-spelling tag/alias
pairs. Field ownership, multiple declarators, parameters, function definitions and
prototypes, block scopes, includes, enums and lexical records use actual AST fields.
Prototype parameter scopes stay local to their signature. Parser reuse has the
same immutable snapshot, cancellation and raw-byte contract as Kotlin.

Unresolved type names retain `struct`/`union`/`enum` namespace prefixes and pointer
stars. Anonymous tags use the source-compatible `__anonymous_at_<byte>` identity.
Their source range identifies the type specifier; synthesized names and declarator
stars need not form one contiguous token. L06/L07 normalize these descriptors to
the shared receiver model. The existing TypeRef model has no pointer variant;
extraction does not invent compiler-level pointer/function-pointer semantics.

Member occurrences retain punctuation-free token ranges and actual receiver
links for `.`/`->`, chained fields, indexing, parentheses and call results. A shared
receiver helper selects the callee rather than its arguments for both frontends.
Unknown receivers remain unresolved during extraction. Includes are facts only;
there is no preprocessing, filesystem include expansion or compiler validation.
