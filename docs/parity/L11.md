# L11 — Completion providers and deterministic ranking

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(intelligence): rank native completion with precise insertion ranges`.

`completion/` implements local scope, receiver member, type, import, keyword,
workspace and snippet providers over immutable semantic snapshots. Contexts carry
canonical language, cursor/prefix, member receiver, import path, raw UTF-8
replacement range and source content hash. Kotlin safe access, C arrow access,
parentheses/casts/chains and generic-language dollar prefixes retain their source
coordinates. Qualified import insertion replaces the complete typed import path;
ordinary insertion replaces only the prefix before the caret, retaining receiver,
operator and suffix. Core CompletionItems require no AST access in E09.

Candidates retain declaration identity, label, insertion text, kind, detail,
provider, scope distance, same-file occurrences and workspace frequency. Local
lookup respects declaration order/shadowing and scopes; workspace/import providers
exclude other functions' local declarations. Members come only from prepared
receiver types with accessibility checks, including nullable/generic/inherited
members. Union suggestions intersect accessible members of every alternative;
different member declarations retain no fabricated common symbol identity.
Unknown receivers return an empty member list rather than text-based suggestions.

Heuristic ranking ports the source weights: prefix .30, scope .15, receiver/type
.25, same-file recency .10, logarithmic workspace frequency .10 and optional score
.10. Existing occurrence indexes supply counts; actual scope distance breaks local
ties. Candidates deduplicate by symbol ID, or kind/label for non-symbol suggestions.
The best equivalent candidate wins independently of provider order. Stable label,
kind, identity, provider, detail and insertion tie-breaks make output deterministic.
The source's Kotlin snippets remain `fun`/`when` declaration starters without
invented template expansion. Keyword/snippet duplicates collapse consistently.

The optional CompletionRanker interface can score existing candidates and cannot
add declarations or resolve identities. Native heuristic scores leave its optional
component zero; no learned model/ONNX runtime is present. Invalid/non-finite scores,
stale source hashes, cancellation and work-limit exhaustion return explicit errors.
Provider emission is bounded to 100,000 candidates/two seconds; output is bounded
to 1,000, with the editor requesting 50. L09 still gates workspace, document,
request and index revision before attaching results.

Nine `kode-intelligence/tests/completion.rs` tests cover basic and cross-file
receivers, chained properties/methods/functions, casts/parentheses/assignments,
nullable generic access, union intersection/identity, this/super/private/protected
visibility, unknown receivers, C typedef/pointer fields, local scope precedence,
declaration order, keyword/snippet/import/workspace providers, empty prefixes,
Unicode/operator/suffix preservation, numbered score evidence, frequency saturation,
provider/file input order, deduplication, limits, stale content and ranker errors.

`kode-tui/tests/completion.rs` additionally feeds real native candidate DTOs into
E09: popup preparation, drawing, acceptance, exact Unicode safe-access and
qualified-import replacements, dismissal and undo all pass. This is a synthetic
integration fixture; L09 attaches the actual application service separately.
