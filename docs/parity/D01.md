All 59 definitions are frozen in declaration order, preserving every class,

Normalized models cover datasource/driver/artifact, project/session, connection
status/test, metadata requests/objects/capabilities and legacy result/error/cell
types. Known serialized fields/defaults remain compatible; unknown config fields
survive, local multi-JAR strings remain unchanged, and provider artifacts/recents
share source families. Template validation covers cycles, coverage, IDs, schemes,
sensitive placeholders and source TLS bypass patterns. Effective lists retain
shared immutable templates instead of multiplying inherited string bodies.

Rust config uses separate versioned user files and explicit imports. OS advisory
locks serialize writers; guarded atomic saves reject changed files. Corrupt/future
state and known symlink/nonregular targets fail visibly and remain intact.
Datasource import preserves IDs, URL/class/coordinate/JAR values, safe properties,
references and unknown fields. Secret driver properties become references to the
private credential store; collisions fail before replacing existing values.
Credential-bearing URLs fail without rewriting or echoing them. Source files are
never changed and existing Rust definitions win on repeat import.

`Secret` has redacted Debug/Display, explicit exposure and no Serialize. Private
files use Unix owner-only permissions, validated on read. The native parser matches
Java properties Latin-1, escaped keys/values, comment/continuation rules, duplicate
keys, unknown escapes, Unicode escapes and valid surrogate pairs. Unpaired UTF-16
units produce an error without lossy replacement or writing original files.

Recents are trimmed/exact/case-sensitive MRU, deduplicated and capped at 12 per
family; seed order and alias/provider families match the source. Known named,
encoded, userinfo and Oracle embedded credentials are rejected while safe
parameters survive. Legacy import filters unsafe recents and preserves source
bytes. The application applies feature export validation before session capture,
save or backup through a generic SessionStore callback; workspace storage retains
opaque feature JSON without depending on database models.

Limits are explicit in CONTRACTS.md: private storage is access-restricted plaintext,
not encryption/zeroization; Windows ACL/native execution and vendor driver behavior
remain D09/Z04 qualification. Unpaired legacy UTF-16 units are retained in the
original and rejected, not replaced. Unsafe credential-bearing definitions fail
visibly until explicitly corrected/imported; they are not silently stripped.
Private/public files are separate atomic writes, so a late public failure can leave
private orphan refs. Worker APIs and E04 identity/rename boundaries do not claim
cross-process filesystem transactions or hard RSS guarantees. D01 does not claim
a JDBC connection or completed database UI. Next task: D02. Full migration remains
in progress.

D02 follow-up qualification found a real lock-release edge when a concurrent
process spawn temporarily inherits a CLOEXEC descriptor before exec. ConfigLock
now explicitly unlocks its owned open description before closing, so a duplicated
or inherited handle cannot retain a completed writer's flock. A deterministic
duplicate-description regression also proves that closing that old duplicate
does not release the next writer's lock. This corrects the earlier attribution of
intermittent parallel-test WouldBlock errors solely to sandbox restrictions.
