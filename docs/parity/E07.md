# E07 — Regex find/replace and search bar

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable and Java 21.0.9, Linux x86_64.

Core search scans immutable snapshots with regex 1.13.1 for ordinary patterns
and fancy-regex 0.19.2 for lookarounds/backreferences/Java assertions. Explicit
translation preserves Java default ASCII classes/case folding, Unicode opt-ins,
scoped flags, quoted literals, scalar escapes, dot/line terminators, multiline/
final-end anchors and common POSIX properties. Match/capture ranges use bytes
across lines. Numeric `$n` replacement uses Kode's custom greedy rule, including
Java 21 BMP decimal digits: missing groups disappear; other dollars/backslashes
remain literal. Replace-all is one revision and undo transaction.

The two-field bar preserves uppercase, Ctrl+F escaped selection prefill,
Tab/mouse focus, Enter/Ctrl+Enter, Ctrl+R/Ctrl+Shift+R, close and Escape.
Counts/active match, error styles, caret/hints and tiny bounds are clipped.
Field clipboard I/O is emitted to the host with delayed-paste identity guards.
Read-only documents remain searchable but cannot be replaced. The two-row search
area shrinks the viewport; closing restores editor focus. Integration corrected
E06's post-hook focus assignment so closing cannot leave invisible field focus.

Actual bounded workers execute scans. Publication checks workspace/request/
document/revision/query/open state. Edits, history, new queries and close reject
old results. Pending actions wait for the current scan and cancel on lost field
ownership. Matches feed shared overlay spans. Render/input do not scan or perform
native I/O. Registry/application composition remains E12/W05.

## Explicit limits and corrections

Unsupported syntax reports useful errors: Java Character `java*` properties,
grapheme `\X`, contiguous `\G`, control/octal escapes, COMMENTS `x`, surrogate
escapes, ASCII case-insensitive backreferences/named groups and escaped ranges
inside ASCII case-insensitive classes. Unicode opt-in matching uses the selected
engine's tables, which can recognize newer characters than Java 21; replacement
digit parsing separately uses Java-compatible Unicode 15 categories.
Patterns are bounded at 65,536 bytes, compiled automata at 8 MiB, matches at
100,000, and fancy backtracking at 100,000 steps per attempt. Limits never publish
partial matches or partially replace text. Zero-width matches are consistently
excluded from count/navigation/replacement, correcting source invisible matches
that could still be replaced. Raw CRLF/final newline survives replacement.

literal/Unicode-numeric replacements, Java flags/classes/line endings, multiline
ranges, lookarounds/backreferences, zero-width progress, errors/cancellation,
stale/read-only rejection and no-op history. All 29 synthetic Java 21 oracle

`java scripts/JavaSearchFixture.java fixtures/editor/search-java21.json`.

including CRLF from Git newline conversion.

counts, replace/undo refresh, stale/closed/edited results, clipboard races, error
styling, tiny geometry and real worker publication/draining shutdown.
