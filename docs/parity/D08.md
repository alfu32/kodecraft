# D08 — SQL editor, statement targeting and results

Status: done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68` (`../kode`, clean).
Reference: `SqlStatementLocator` / `SqlQuery.kt`, its original locator tests,
`SqlConsoleManager.kt`, `SqlResultPanel.kt`, `SqlSessionSaveDialog.kt`,
`SqlStatementMenu.kt` and Main's console/save/toolbar/dispatch/sizing helpers.
Prerequisites D05, D07, E12, E09 and L02 have implementation/evidence.

Changed components:

- Native `statement.rs` targets actual UTF-8 selection offsets or current SQL,
  handles quoted semicolons/comments, PostgreSQL dollar/E strings, nested standard
  comments, MySQL quotes/backslash/hash/dash/version comments and identifier dollar
  signs. EOF after a terminator selects only the last statement. Explicit script
  remains one JDBC execution. Diagnostics omit SQL bodies.
- Native `console.rs` preserves source counters, IDs/titles/default comments,
  catalog/schema/autocommit preferences and unknown fields. Request guards reject
  stale/double completion and removing running sessions. History retains timestamps,
  duration/success/unknown outcome with 512 per console and 4,096 / 16 MiB globally;
  an ordered eviction index avoids rescanning all consoles per eviction.
- Database panel `console`, `results`, `session_dialog`, `statement_menu` and app
  SQL composition wire real shared editor documents, Ctrl+Enter/current/selection,
  Ctrl+Shift+Enter/script, Escape/cancel, Ctrl+Alt+A/C/R shared transactions, toolbar
  mouse actions, right-click execution menu and per-console context dialogs.
- Hover Execute captures a rope and selection, computes on a worker and publishes
  only for matching document revision/selection. Find bar and editor popup priority
  remain intact. The editor stays usable while queries run or results arrive.
- Results retain typed chunks per console and expose sets/messages, type labels,
  NULL, bounded binary hex/size, clipped controls/Unicode, sampled bounded widths, row/column
  scroll, elapsed time, limits/incomplete previews, warnings/chained SQL errors,
  unknown outcomes and cancellation acknowledgement separately from completion.
  Alt navigation preserves editor focus; clicks give results their own focus.
- SQL owner saves use captured text and native guarded atomic writes. Existing
  unowned targets/external changes are retained, failures keep the path/buffer,
  and successful old snapshots cannot mark newer text saved. Unsaved SQL buffers,
  identities and bindings persist on W03's worker and restore without Java or SQL.
  Quitting dismisses an unsubmitted filename dialog and flushes the buffer.
- Execution options bind catalog/schema atomically with SQL in the helper's owner
  job. Null resets login defaults, preventing interleaving consoles from inheriting
  each other's context. Cancel retries capture the same execution ID and are
  bounded/tagged. Services stop the executor before connections/helper teardown.

Public contracts are recorded in `docs/migration/CONTRACTS.md`. JDBC wire shape
already supported optional nullable context; D08 exposes it in the native options.
No separate set-context RPC precedes execution. Restoring a session never restores
a live transaction or automatically connects. History/results remain in memory,
matching the source's persisted session model.

Acceptance / qualification on stable Rust/Cargo 1.99.0, Java 21.0.9,
Maven 3.9.16, Linux x86_64, synthetic fixtures only:

- Six locator regressions translate all original cases and add repeated Unicode
  selection offsets, EOF safety, comments-only input, quoted identifiers, dollar
  bodies, nested comments, MySQL lexical cases and invalid byte boundaries.
- Four console regressions cover original identities/counters/restore/bindings,
  unknown fields, stale requests, double finish, running removal, bounded history
  and immutable metadata/buffer capture during newer edits.
- `database_results.rs` exercises multiple sets, chunk boundaries through row
  1,199, NULL/binary/type labels, update counts including i64 max, warnings/chained
  SQLSTATE/vendor errors, Alt navigation, independent mouse focus, tiny viewports,
  terminal control clipping and cancel acknowledgement versus unknown completion.
- App regressions cover real workers for hover targeting without selection change,
  find Ctrl+Enter precedence (UX-106), SQL file save, external edit conflict with
  retained path, dirty buffer/context/session restart and monotonically increasing
  restored console IDs. Closing with queued/open filename dialogs is bounded;
  repeated Cancel captures only the original execution identity.
- The actual Rust→Java→H2 app executes current versus script, verifies EOF does
  not replay an earlier INSERT, reads typed/limited results, commits/rolls back,
  toggles shared autocommit, switches consoles with distinct schemas/results,
  scrolls results while arrows still edit (UX-104), cancels a billion-row aggregate
  while typing, and retains exact SQL/focus/history (UX-101). Error completion also
  preserves focus. Native H2 qualification verifies concurrent schema bindings and
  explicit-null reset to PUBLIC.
- `python3 scripts/test-sql-terminal.py`: four real PTYs passed at 100×34 and 60×18:
  Ctrl+Enter→result→save file→quit dirty SQL→restart. Restoring does not start Java;
  owned helpers are reaped, credentials remain untouched and terminal modes/termios
  are restored. [Recorded PTY evidence](D08-pty.json).
- `bash scripts/test-jdbc-bridge.sh`: **62 Java / 75 Rust tests passed** (48 backend,
  27 database UI/service tests), including every opt-in actual-helper case.
  `cargo test --workspace` passed before the final cancel-retry/closure and MySQL
  lexical refinements; the final focused app/results/editor-host run passed all
  19 cases, and the final helper script above covers all refined database code.
  Database/TUI all-target clippy with `-D warnings`, workspace check, formatting,
  diff checks and CLI build pass. The four PTYs passed before those narrow final
  cancel/lexical changes; they use unchanged standard H2 SQL targeting.

The locator is not a complete procedural SQL parser. Nondefault session SQL modes,
vendor block delimiters and vendor databases beyond actual H2 remain qualification
limits; explicit selection/script supports exact user-selected input. Bounded
previews/history are retention limits, not a hard RSS or frame-latency guarantee.
Removed-source buffers are retained in session state for recovery. Full migration,
busy/crash/workspace/vendor matrix and release/platform qualification remain D09,
E13 and Z04. No user credentials, private database or developer session was used.
