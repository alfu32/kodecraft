# E06 — Editor input, hit testing, scrolling and focus

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable, Linux x86_64.

`editor/input.rs` keeps view/caret/scroll state per document and focus owner.
Normalized keyboard commands call the core movement/edit/history operations;
logical arrows stay logical while PageUp/PageDown use shared visual rows and
retain segment columns. Wheel steps scroll three rows, Alt steps nine, clamp
and preserve the caret. Navigation reveals the caret even when it cannot move.
Header/search offsets, nested absolute pane rectangles and modifiers stay intact.

Text/tab/escape/gutter hits use the painted map. Left press focuses the editor
and anchors selection; captured drag extends it in either direction. Release
outside clears capture. Focus loss clears capture and pending paste requests.
Captured pointers beyond the body clamp and autoscroll on events/animation ticks;
this adds usable edge dragging to the source's header-boundary rejection.

Popup/search/gutter/minimap/navigation hooks consume input before base editing.
Hook owners receive original events and shared geometry. Unfocused editors and
editors under another owner's capture cannot consume keys/paste/pointer input.
Host effects carry raw copies, save/search/completion requests and edit deltas.
Native clipboard I/O remains on the platform worker path: delayed paste tickets
check request, document, revision, selection, focus and search ownership before
one grouped edit. Read-only mutations stay guarded by the core document.

100-line viewport/page and 3/9 wheel assertions, scroll clamping, reverse wrapped
escape selection, raw replacement/undo, release outside, autoscroll/focus loss,
popup/search/navigation consumption and all modifiers in nested panes, delayed
clipboard races, read-only and unfocused input, logical arrows and tiny sizes.
