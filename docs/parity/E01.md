# E01 — Rope document and coordinate conversions

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Toolchain tested: Rust/Cargo 1.99.0 stable, Linux x86_64.

Changed paths: core `document/{text,positions,snapshot}.rs`, typed coordinate error,
document tests, Ropey dependency/lockfile and shared contracts.
Source buffer/state/Tree-sitter UTF-16 adapter and VisualLine behavior were audited.

Ropey 1.6.1 (MIT) is pinned with default features disabled and SIMD enabled.
Its selected manifest/source and [official API](https://docs.rs/ropey/1.6.1/ropey/struct.Rope.html)
were inspected. LF-only recognition preserves the source's treatment of standalone
CR and Unicode line separators. An empty document has one logical line, one final
LF adds exactly one empty logical line, and CRLF/raw source bytes remain exact.

`Document` owns identity/origin/language, monotonic revision, saved baseline and
read-only capability. Validated edits reject stale, reversed, out-of-range and
scalar-interior coordinates; no-op/rejected edits never advance the revision.
Immutable `TextSnapshot` uses a cheap rope clone with line/slice/chunk iterators.
Portable service text is materialized lazily once per revision and shared between
snapshots. Editing the source never changes earlier snapshots.

Byte/scalar/logical-line/UTF-16 adapters round-trip every scalar boundary in the
ASCII, tabs/controls, emoji, combining, wide, LF/CRLF and EOF fixtures. Legacy
surrogate-interior UTF-16 columns clamp to the preceding scalar boundary. Invalid
strict source coordinates return typed errors. Terminal cells are absent from the
document model. Logical UI content excludes CRLF terminators; raw source position
adapters retain their byte mapping including the CR before LF.
