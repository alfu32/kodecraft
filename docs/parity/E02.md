# E02 — Movement and selection commands

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Toolchain tested: Rust/Cargo 1.99.0 stable, Linux x86_64.

Changed paths: core `editor/{movement,selection}.rs` and movement integration tests.
Original cursor/selection/word helpers and key dispatch were read and ported.

`CaretState` retains directional anchor/head, validated explicit selection,
clamped restored positions, select-all, selection clearing and raw source extraction.
Logical left/right traverse scalar and line boundaries, treating a CRLF break
atomically. Up/down clamp to the next logical line using the current logical
column; they preserve the source's behavior of not restoring a hidden preferred
column after a short line. Top/bottom moves go to first-line start/last-line end.
Home/End, document bounds and ASCII identifier/punctuation/whitespace word jumps
match the source. Shift movement preserves the original anchor and plain movement
clears selection. Visual PageUp/PageDown targets come from layout; core movement
never reads or invents terminal row coordinates.

Five tests pass: Unicode/CRLF scalar movement, short/empty line behavior,
forward/reverse multiline selections, word punctuation/whitespace/`$`/underscore
boundaries, Home/End/page targets and invalid explicit selection rejection.
Acceptance: UX-008–013/017. Empty document and repeated start/end movement are safe.

Passed: `cargo test --offline -p kode-core --test movement`; `cargo check --offline
-p kode-core`; `cargo fmt --all --check`; `cargo clippy --offline -p kode-core
--all-targets -- -D warnings`. No terminal check applies to core movement; actual
wrapped paging/mouse/scroll connection remains E06.
