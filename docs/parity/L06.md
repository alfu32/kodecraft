# L06 — Names, scopes, imports and symbol resolution

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(intelligence): resolve lexical names imports and type relations`.

The native resolver indexes complete file deltas before binding names, so results
are independent of input order. It resolves the actual lexical scope chain,
declaration order, imports/aliases/wildcards, package globals, declared types and
inheritance/alias/member relations. Private/protected visibility is checked against
the current owning type and inheritance graph. Sibling locals, unrelated members,
unimported packages and ambiguous equally visible identities remain unresolved.
Local values can shadow callable names without falling through to another function.
Snapshot visibility also excludes nested declarations from global candidates and
uses the actual enclosing type for inherited members.

C tags and ordinary typedef/value names use separate lookup contexts; the narrowest
type-specifier range identifies a tag reference. Pointer decorations normalize to
the existing shared receiver model. Anonymous/same-spelling aliases, nested alias
field types, enums and include dependencies are retained. C enum declarations use
the enclosing ordinary scope while retaining enum ownership. Direct includes use
prepared path identities without filesystem reads. The best-effort C fallback can
bind an unambiguous workspace declaration when no include supplies one; it performs
no preprocessing or compiler validation.

Declared nullable/generic/function shapes, forward callable/type references,
inheritance, `this`/`super`, receiver members and call/type/import/reference file
dependencies are prepared before query publication. Function-arrow precedence
keeps nullable return types distinct from nullable function values. Unresolved
occurrences are returned explicitly for later invalidation. Traversal is cancellable,
cycle-safe and bounded by five seconds/two million resolution operations; recursive
type parsing is bounded separately. L07 adds inference from initializers/assignments;
L08 owns incremental invalidation and generation advancement.

L06 found a grammar regression in kotlin-ng 1.1.0: valid inline class members could
cause subsequent declarations to disappear from the tree. An isolated native
comparison selected `tree-sitter-kotlin-sg` 0.4.1 on the same runtime 0.26.13.
The frontend now consumes its real identifier/import/statement/navigation/binding/
literal nodes. ABI/node-field fixtures were regenerated for all 28 parser variants,
and the original nine Kotlin extraction tests still pass. Inline class regression
tests retain every declaration even where the upstream parser reports a synthetic
missing-semicolon recovery marker. These markers are partial syntax status, not
compiler diagnostics. Binding APIs were checked against actual sources and the
[pinned upstream binding](https://docs.rs/tree-sitter-kotlin-sg/0.4.1/tree_sitter_kotlin_sg/).

Nine `tests/name_resolution.rs` tests exercise identities/references and forward
functions, reordered files, shadowing/declaration order, imports/aliases/wildcards,
ambiguity, inherited visibility, private globals, unknown names/receivers, nullable
generic/function types, cyclic aliases, callable shadowing, C namespaces and enum
scope. The actual C frontend→resolver→SQLite→restart test reproduces the source's
tag/typedef/pointer/anonymous/same-spelling scenarios and preserves three resolved
member references, without Java or fabricated production facts.
