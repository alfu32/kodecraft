# L02 — Keyword highlighting and incremental parser registry

Status: done. Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Summary: `feat(syntax): qualify keyword resources and incremental native parsers`.

`kode-syntax` implements the source keyword/color catalogs, keyword completion
extraction, markup tag/attribute/string and CSS class rules, ordered configurable
regex grammars, and explicit resource diagnostics. All 248 bundled language regexes
compile; [the audit](L02-patterns.json) records the result. C+, systemd, JSX/XML/CSS,
punctuation, ordered captures, malformed resources and byte ranges after Unicode
prefixes have focused tests. Custom grammar loading rejects path traversal and
bounds file size/count. The shared Java-pattern backtracking translation preserves
ASCII word boundaries; the existing Java search oracle remains passing.

The [manifest](../../resources/grammars/manifest.json) pins Tree-sitter 0.26.13 and
the 25 upstream binding packages supplying 28 usable grammar variants. These cover
the source's selected language inventory plus distinct TSX, Markdown-inline and
OCaml-interface variants. Rust retains keyword fallback, matching the source's
absence of an active Rust Tree-sitter binding. Every grammar loads through safe
upstream bindings; application code contains no unsafe FFI. ABI 14/15 and node-type
hashes are recorded alongside package versions, upstream links and MIT licenses.
The [node-field fixtures](../../fixtures/languages/parsers/node-fields.json) record
actual parsed nodes, fields, source text and UTF-8 byte ranges for every variant.

`ParserSession` reuses trees after a scalar-boundary-safe contiguous InputEdit;
published `ParsedDocument` values retain immutable old trees/source snapshots.
Kotlin and C tests compare reused and fresh trees, lexical spans and diagnostics
through Unicode replacements, CRLF input, insertions and length-changing edits.
Parser work checks cancellation, a two-second budget, 16 MiB source and one million
node limits. Failed/cancelled parses preserve prior published trees and allow later
recovery. Syntax requests use the F03 bounded blocking scheduler and exact
workspace/request/document/revision tags. Grammar absence/failure returns usable
keyword highlighting with an explicit status message.

Acceptance commands passed on stable Rust 1.99.0:

- `python3 scripts/build-parser-fixtures.py` — all 28 native samples parse;
  catalog diagnostics empty.
- `cargo test --offline --workspace --quiet -j2` — 215 tests passed.
- `cargo fmt --all --check`.
- `cargo check --offline --workspace --all-targets`.
- `cargo clippy --offline --workspace --all-targets -- -D warnings`.

Focused tests are `kode-syntax/tests/{keywords,regex_grammar,parser}.rs` and
`kode-core/tests/search_captures.rs`. The final Unicode replacement extension of
the incremental test also passes independently. Native APIs were checked against
the pinned [runtime documentation](https://docs.rs/tree-sitter/0.26.13/tree_sitter/)
and actual binding sources. No manual terminal check applies to this worker API;
editor attachment and stale-overlay behavior belong to E11/L09. Tree-sitter
recovery is partial syntax information, with no compiler guarantees. Decoder,
parser and regex budgets bound service work rather than claiming a process RSS
limit. Next ready task: L03.
