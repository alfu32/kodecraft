## Implemented boundary

Java `queries/QueryService.java` executes SQL on D04's serialized connection
owner. It iterates mixed result sets and 64-bit update counts, emits ordered typed
events, preserves warnings and chained SQL errors, and reports elapsed time,
transaction usability and authoritative connection state. Result-set, statement
and large-value cleanup stays on the owner with the driver's context classloader.
`CellPreview.java` preserves NULL separately from empty text, exact decimal and
temporal strings, boolean text and base64 binary. Character streams are bounded
on UTF-8 scalar boundaries; LOBs/XML/arrays are read as bounded previews and freed.

Native `execution.rs` exposes inert construction, tagged execution IDs, watched
snapshots, explicit cancellation and tracked shutdown. A dedicated notification
consumer validates every sequence and result transition and retains immutable
row chunks independently of UI painting. Final `eventCount` provides a barrier:
completion cannot overtake buffered rows. A known final survives immediate helper
exit; missing/malformed events fail visibly, preserving prior rows and uncertainty.
Connection revisions prevent late execution replies from restoring old context.

Cell previews are at most 64 KiB, rows 512 KiB and result sets 256 columns. Batches
contain at most 200 rows and are split near 2 MiB encoded; frames remain below
8 MiB. Default row cap is 500, configurable through 100,000; one extra JDBC row
distinguishes an exact result from a limited preview. Native retention is charged
against 32 MiB per preview and 64 MiB shared across retained snapshots. Clones
retain their budget permits. Reaching the limit requests cancellation and marks
the preview incomplete; it never silently presents dropped rows as a full result.
SQL-derived column labels, cell bodies and remote error messages are omitted from
Debug output. Protocol examples, schemas and the shared query fixture agree on
the required final event counter.

## Cancellation and ownership

Independent control dispatch and bounded cancellation workers keep input and
cancel acknowledgements responsive while JDBC execution or output is blocked.
A bounded early-cancel registry handles priority cancellation arriving before
ordinary execute dispatch. Cancellation retries cover drivers resetting their
cancel flag at execute entry. The owner waits for its cancellation call to finish
before closing the statement or starting another job, preventing late
connection-wide cancellation from targeting the next statement.

Requested/unsupported acknowledgements are exposed separately from final outcome.
Unsupported or hanging cancel does not produce false completion; an uncooperative
driver may require disconnect/abort or explicit helper restart. Received rows
remain available. Dropping the UI wait requests cancellation while tracked work
continues until the original final or a visible failure. Executor shutdown joins
that work before Connections shutdown. Cancellation never claims commit or rollback,
and no SQL is replayed after timeout or helper death.

## Acceptance evidence

Qualified on stable Rust/Cargo 1.99.0, Java 21.0.9, Maven 3.9.16, Linux x86_64.
All databases, credentials, helper roots and traces are synthetic test fixtures.

- `bash scripts/test-jdbc-bridge.sh`: **54 Java tests** and **30 Rust integration
  tests passed**, including all four opt-in tests against the actual shaded Java
  helper (13 bridge, 5 connections, 4 drivers, 8 execution tests).
- Java query tests cover actual H2 selects/DDL/updates, NULL/empty/binary/exact
  decimal/nanosecond timestamp/boolean conversion, 200-row batching, exact versus
  exceeded row caps, bounded Unicode/CLOB/BLOB/array/wide rows; scripted mixed
  result sets and maximum 64-bit update counts; warnings and later-result errors
  preserving earlier results; failed manual transactions; early cancellation,
  execute-entry retry, unsupported/hanging cancellation and next-query isolation.
- Native tests cover inert construction, disconnected validation, eight concurrent
  executions, ordered typed chunks before final, explicit cancellation and retry,
  dropped waits, crash with partial rows and no replay, malformed sequence and
  known final immediately before EOF. Actual H2 exercises DDL, streamed values,
  commit/rollback, row limits, context and failed-transaction recovery through the
  native client. Preview tests cover invalid shapes/base64/order/oversize cells,
  retained budgets across clones, and redacted diagnostics.
- `python3 scripts/test-jdbc-query-backpressure.py`: actual Java/H2 query fills a
  real OS stdout pipe; the script proves it is not writable, sends cancellation
  through stdin before draining, observes the priority acknowledgement and ordered
  incomplete final, then successfully executes a new query and reaps the child.
  [Machine-readable evidence](D05-backpressure.json) records capacity, buffered
  bytes, event counter agreement and process exit without cell or stderr bodies.
- `cargo test --workspace`: **434 passed / 4 opt-in ignored**; those four passed
  separately above. Final database unit tests pass after the column Debug check.
- `cargo check --workspace`, database/TUI clippy with `--all-targets -- -D warnings`,
  formatting and diff checks pass. `cargo build -p kode` passes. The catalog check
  still verifies all 59 source driver definitions and exact URL templates.

The wire and retention limits bound previews and queued data, not total process
RSS: drivers can allocate before a getter returns. Unsupported JDBC accessors
produce explicit SQL failures. Native execution waits are bounded to 600 seconds;
acknowledgement and event-barrier waits are separately bounded. No guarantee is
made that arbitrary vendor calls honor interruption or cancellation. External
vendor databases, console/result UI and non-Linux qualification remain D08/D09/Z04.
JDBC iteration and cancellation behavior follow the Java 21
[Statement](https://docs.oracle.com/en/java/javase/21/docs/api/java.sql/java/sql/Statement.html)
and [ResultSet](https://docs.oracle.com/en/java/javase/21/docs/api/java.sql/java/sql/ResultSet.html)
contracts. This card does not complete the overall migration.
