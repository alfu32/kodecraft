# R10 — OAuth acquisition and browser authorization

Status: done

M002 and B008 are implemented in the production OAuth service, request form,
application jobs, Send/collection runner and raw preview. The final build passes
the acceptance checks below, including real browser login and HTTPS interception.

The default callback is `https://localhost:0/callback`. Kode binds a free loopback
port and serves HTTPS with an ephemeral, in-memory certificate/key. Imported
Postman callback defaults resolve to this local listener. The actual callback URI
is displayed in Auth; the UI explains the self-signed certificate trust prompt
and provider redirect registration. No trust-store modifications or credential
persistence occur. Optional HTTP loopback and explicitly pasted remote redirects
remain available. URI/path/query ownership, duplicate response fields, CSRF state
and temporary OAuth 1.0 tokens are checked. Wrong callbacks remain pending;
matching denial terminates the flow. Cancellation/drop releases the listener,
including during an incomplete TLS handshake.

OAuth 2.0 supports PKCE S256 authorization code, client credentials, explicit
refresh and device authorization/polling. OAuth 1.0 supports temporary/access
credential exchange. oauth2 5.0.0 adapts the existing reqwest transport; local TLS
uses tokio-rustls 0.26.6 and rcgen 0.14.10. Endpoint requests disable redirects and
retries, bound responses, and sanitize raw errors. Cancellation/deadline includes
network, callback and device waits. Device polling handles pending/slow-down and
expiry. Newly acquired tokens and client captures redact Debug output.

The Auth tab provides settings, Acquire, Cancel, Refresh, Clear, a wrapped login
URL, copy/select URL and a flow-bound redirect dialog. Token sets are runtime-only,
limited to 32, and keyed by stable request identity within the workspace. Changed
resolved settings or expiry reject execution before network I/O. Switching views
does not transfer tokens, removal/replacement prunes them, and shutdown cancels
pending flows. Failed explicit refresh preserves the prior token. Captured live
and unopened environment drafts are used consistently for acquisition and preview.

Send and collection runs capture token overrides before request resolution. Old
token placeholders are skipped while other validation remains active. Raw and
transaction previews mask runtime Authorization; actual wire headers carry the
credential. Session, collection exports and restart retain no acquired tokens.

Validation:

- Full `cargo test -p kode-rest -p kode-tui` passed. Two existing Java/H2 integration
  tests remain ignored by the default suite and are qualified by the JDBC script.
- Thirteen OAuth service cases cover real PKCE verifier hashes, HTTP/HTTPS local
  callbacks, wrong state/URI/duplicates, denial, remote pasted redirects, public
  and confidential clients, refresh rotation/expiry, malformed/oversized/redirected
  endpoint responses, redacted errors, device pending/slow-down/success and
  cancellation, OAuth 1.0 exchange, protected HTTP and changed settings.
- The runtime ownership test switches requests while authorization waits, delivers
  the result to its original owner, removes that owner, checks a reused path does
  not inherit credentials, and shuts down a second pending HTTPS listener.
- Form tests cover copying the complete long URL, bounded wrapping, redirect
  dialog flow identity, no model mutation and existing masked auth controls.
  Buffer tests cover captured environment drafts and readonly request previews.
- [Eight actual PTY/browser and restart cases](R10-pty-browser.json), generated by
  `scripts/test-rest-oauth-terminal.py`, pass at 100 and 60 columns. Real Chrome
  fills a synthetic provider login form and follows its redirect to Kode's HTTPS
  callback. The provider checks the actual S256 verifier and redirect URI; Kode
  refreshes then sends an authorized request. Client-credentials acquisition also
  refreshes/sends. Each session restarts with no token; saved collection content
  is unchanged, no acquired secret is persisted, callback sockets close and
  terminal modes restore. Only isolated browser test contexts bypass trust for
  the generated self-signed certificate; production endpoint verification stays on.
- All 22 existing authentication PTYs also pass after adding OAuth controls.
- Affected all-target clippy with `-D warnings` passed; workspace/fmt/ledger and
  521-entry locked dependency credits pass at the final checkpoint. The final
  rebuilt binary passes all eight browser/restart cases; the environment capture
  follow-up passes six buffer tests and the runtime ownership suite.

Fixtures use synthetic credentials and local providers. Real provider login and
redirect registration depend on the user's provider configuration. Self-signed
localhost HTTPS requires browser acceptance; no public CA trust is claimed.
