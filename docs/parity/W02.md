# W02 — File tree, file actions, refresh and project panel

**Status:** done

Source baseline: `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.
Validated on Rust/Cargo 1.99.0 stable, Linux x86_64 GNU.

`kode-workspace/src/{tree,watch}.rs` supplies lazy expanded directories, sorted
directory-first flattening, prepared size/count/status metadata, cancellable worker
refreshes and critical file-operation completions. Tree flattening is linear in
visible entries and does no IO. Browser policy is independent of the index: hidden,
Git-ignored, build and outside-source entries remain visible, while both legacy
and Rust session metadata are hidden. Links remain visible but directory links
are not traversed, avoiding cycles and external tree operations.

The files panel renders root `[change][+d][+f]`, `[+]/[-]/[=]` row markers, hovered
rename/create/delete controls, modal name entry and a separately scrolling recent
list with dirty/removal indicators. Mouse hits use absolute nested pane coordinates;
keys navigate/open/collapse the tree. Refresh preserves expansion, selection,
scroll and an active name dialog. Explicit failures remain visible, and failures
trigger refresh because recursive deletion can fail after partial filesystem work.
Labels escape controls rather than sending raw filenames to the terminal.

Create uses exclusive file/directory creation. Linux GNU renames use atomic
`RENAME_NOREPLACE`; existing targets cannot be overwritten. Path validation rejects
root/metadata modification, multi-component names and external symlink parents.
Successful moves reconcile tree state, recents, configured source roots/exclusions
and open document paths. Document retargeting advances revision without replacing
dirty text, saved baseline or undo/redo. `EditorDocuments` reserves affected paths
before a worker operation: new saves wait, existing saves prohibit the operation,
and critical completion retargets each save baseline before releasing the reservation.
Deleted dirty documents remain owned; their existing disk conflict guard protects
against silently recreating a deleted file.

Native notify invalidations use a constant-memory dirty bit, ignore read-access
events and coalesce for 150 ms; a five-second timer works when notifications fail
or are dropped. Watcher setup/drop and filesystem work belong to workers. The
folder picker supports root/nested selection, folders-only or files-and-folders,
keys, wheel, independent scrolling, small bounds and modal focus restoration.
Project controls emit typed source/exclusion edits and rescan commands. Rescan
progress checks the job tag, keeps scan/index progress supplied by their owner and
requests cancellation through its actual token; completion waits for worker ack.

Acceptance UX-030/031/110: six workspace and seven panel regressions cover the
original FileTreeTest metadata fixture, lazy expansion/status/count ordering,
refresh races, external native events, fallback coalescing, filenames with spaces,
failed rename/delete, overwrite and path rejection, safe symlink deletion, bounded
worker delivery, tree/recents keys and mouse controls, modal focus, preserved edits,
scroll/selection, rescan cancellation, empty/tiny panes, and actual saving after an
open folder moves with dirty undo/redo retained. All **139 workspace tests** passed;
workspace check, format check and all-target Clippy with warnings denied passed.

Shell scheduling/publication of these typed commands is W05; session persistence
is W03; MIME classification is V01. Native Windows execution and other target
qualification remain Z04. Unqualified targets return an explicit unsupported
rename instead of a racy overwrite; `std::fs::rename` replaces existing destinations
on Windows too and is not used as a fallback. Manual whole-app terminal interaction
follows shell composition in W05.
