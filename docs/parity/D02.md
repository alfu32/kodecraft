## Boundary and implementation

Read the frozen DatabaseService boundary, F03 process/resource helpers, P02's owned
client actors, the D02 task card and JDBC.md. The original Kotlin tree remains
unchanged at `7d3e5953ec2de75f2b5e9c44fb3e65549d39ec68`.

`protocol/jdbc-v1/` defines four-byte unsigned big-endian lengths, strict UTF-8,
JSON-RPC 2.0 objects/string IDs, hello-first version negotiation, errors, optional
fields, notifications and schemas/fixtures for all 15 planned methods. Both Rust
and Java run the same envelope, operation and query fixtures. Query DTOs retain
NULL versus empty text, base64 binary, Unicode and exact decimal display strings.
The operation/schema coverage tests check shared method coverage and framed round
trips; they are not a general JSON Schema validator or a claim that future method
handlers exist. Only actually registered methods appear in hello capabilities.

The codec rejects zero/oversized/truncated/poisoned frames, invalid UTF-8/JSON,
batches, malformed envelopes, out-of-range error codes and unpaired surrogates.
Frames are at most 8 MiB, value nesting at most 64, names/IDs at most 128 UTF-8
bytes without controls, and numeric tokens at most 1,000 characters. JDBC numeric
values use strings rather than JSON numeric representation. Input diagnostics do
not quote untrusted payloads.

The Java 21 helper uses pinned Jackson 2.21.4. This is a maintained 2.21 LTS line
([release policy](https://github.com/FasterXML/jackson/wiki/Jackson-Releases)); it
is not a claim to use Jackson's latest major. The shaded JAR relocates Jackson
under `kode.jdbc.shaded.jackson`, leaving vendor loaders their own namespaces.
Apache Maven Shade's [packaging/relocation support](https://maven.apache.org/plugins/maven-shade-plugin/)
is used with separate unshaded input, so repeated builds do not shade an already
shaded JAR. Build settings/toolchains/cache are isolated from user Maven settings,
credentials and startup options. Maven is a build dependency, not a runtime
dependency; `java -jar` runs the packaged helper.

Production bootstrap captures the actual protocol stdout and redirects System.out
before initializing the server or loading a driver. Reader, ordinary dispatch,
control dispatch and output writer are independent. Four ordinary workers and
two control workers have bounded queues; pending bodies retain byte/slot permits
until completion. Ordinary output waits with cancellation checks; control output
has reserved priority/capacity and fails visibly on overflow. A query's own final
response shares its events' FIFO and cannot overtake its rows.

Rust `bridge::runtime::Runtime::new` performs no I/O. First explicit JDBC work
validates Java lookup (configured/KODE_JAVA, JAVA_HOME, PATH), requires Java 21+,
locates KODE_JDBC_HELPER or the packaged `jdbc/kode-jdbc-bridge.jar`, starts one
helper and validates hello. Calls reuse that process; a failed running epoch
requires explicit restart, producing a new epoch and invalidating old IDs. Missing
Java/helper/version failures are typed, actionable backend states for D07's panel.
The native editor can start without any Java executable or DB configuration.

Request IDs are never reused within an epoch. Rust reserves eight control pending
slots and 1 MiB separately from 64 ordinary calls and 32 MiB of outbound payloads.
Queued cancellation atomically prevents later submission. Timeout/cancellation
after writing could have begun cannot prove rollback; mutating operations report
unknownOutcome. Known SQL/transaction/context operations are treated as mutating
even if a low-level caller passes false. No operation is automatically replayed.
Dropping a wait does not stop JDBC: query.cancel/driver.cancel use independent
control requests by operation ID, and acknowledgement is not completion.

The reader drains independently of TUI painting. Up to 32 notifications/32 MiB
are retained. Overflow explicitly disconnects the helper, preserves received
preview data and marks pending mutating outcomes unknown; query data is never
silently dropped. Feature consumers in D03/D05 must drain independently of paint
and route/coalesce progress separately from query data.

Startup/probe futures, pipes, stderr and reaping are owned. Dropping startup or the
last owner triggers cleanup; explicit workspace shutdown joins startup and live
actors, allows bounded graceful shutdown, then kills/reaps the F03-owned process
group. Buffered final responses drain before natural child exit is classified.
The stderr tail is bounded to 64 KiB; public diagnostics expose only a redacted
indication because vendor/JVM output may contain secrets. Debug/Display omit all
remote error bodies; an explicit accessor retains structured data for typed feature
decoding/redaction, rather than losing future SQLSTATE/vendor/chained error fields.

## Failure and regression evidence

Rust fake-helper tests exercise fragmented UTF-8 hello, adjacent frames, concurrent
out-of-order IDs, blocked work with independent cancellation, 64-call ordinary
saturation with working reserved control slots, malformed/poisoned output,
incompatible protocol, startup timeout, crash with large secret-bearing stderr,
notification overflow with retained ordered data, cancelled/timed-out waits and
late replies, dropped startup/live owner, descendant termination, missing/old Java,
missing helper, shutdown during version probing, and dropped lazy startup cleanup.
The timeout test records PIDs in the parent factory, so even cancellation before
the child interpreter starts proves process reaping without relying on a child
writing a PID file within 150 ms.

The blocked-pipe regression queues a mutating request behind a large frame, cancels
it, resumes the peer and verifies its method was never received. The structured
remote-error regression preserves SQLSTATE through explicit access while ensuring
the synthetic secret never appears in Debug/Display.

Java tests exercise the same codecs/fixtures, single-byte input reads, bounds,
hello/unknown method/sanitized errors, out-of-order asynchronous completion,
cancellation/ping/shutdown with all four ordinary workers blocked, bounded output
wait cancellation, control priority and own-final-after-row ordering. An actual
child invokes production bootstrap, prints simulated driver System.out, proves
framed stdout remains clean, sees the marker only in stderr, and exits on stdin
EOF. Rust separately runs the actual shaded Java 21 JAR to prove lazy concurrent
reuse, ping, unknown methods, failed epoch retention, explicit new-epoch restart,
graceful shutdown and process reaping.

Broader validation exposed D01's inherited-description lock-release edge: closing
only the owning FD can retain its flock in a briefly inherited/duplicated open
description. ConfigLock now explicitly unlocks before closing without unlinking
the persistent lock path. A deterministic regression verifies immediate reacquire
while the old duplicate remains open, and proves closing that old duplicate cannot
unlock the next writer. This corrects the earlier sandbox-only attribution.
